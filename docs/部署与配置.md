# 部署与配置

面向把服务端长期跑在 Linux 服务器上的场景。单机版（本机自用）不需要 systemd，直接启动即可。

## 1. 两种运行方式

| 方式 | 启动参数 | 监听 | 登录 |
| --- | --- | --- | --- |
| 单机版 | 无 | `127.0.0.1` 随机端口 | 启动时打印的一次性 token 链接；首次提示中可设置本机口令，设置后改为口令门禁，默认 30 天免输（凭据存 macOS 钥匙串） |
| 网络版 | `--server` | `config.toml` 的 `listen:port`（默认 `0.0.0.0:8080`） | 用户名 + 口令，带 CSRF 校验与登录限流 |

单机版不读 `server.listen`/`server.port`，只绑定本机回环地址。

## 2. 配置文件

### 2.1 查找顺序

1. `--config <文件>`（显式指定，文件不存在直接报错）
2. 环境变量 `XIAOTU_CONFIG`
3. `<数据目录>/config.toml`（存在就加载，不存在则用内置默认值）

数据目录由 `--data` 或配置文件里的 `storage.data_dir` 决定。注意顺序：**配置文件的默认位置按命令行 `--data`（或系统默认数据目录）计算**，配置文件里的 `storage.data_dir` 不会反过来改变「去哪里找配置文件」。需要放在别处时用 `--config` 指明。

### 2.2 支持的键

只支持下面这个 TOML 子集：段 `[server]`、`[storage]`、`[log]`、`[sales]`，键值支持双引号字符串和整数，`#` 起注释（字符串内的 `#` 不算）。

| 键 | 含义 | 默认 |
| --- | --- | --- |
| `server.listen` | 监听地址 | `0.0.0.0` |
| `server.port` | 监听端口，1–65535 | `8080` |
| `storage.data_dir` | 数据目录（`app.db`、默认 `backups/`） | 系统应用数据目录 |
| `storage.backup_dir` | 备份目录；空串表示 `<数据目录>/backups`，相对路径按数据目录解析，绝对路径原样使用 | 空（`<数据目录>/backups`） |
| `log.level` | `debug` / `info` / `warn` / `error` | `info` |
| `log.dir` | 日志目录 | `<数据目录>/logs` |
| `sales.credit_limit_mode` | 客户信用额度超额行为：`warn` 提示并二次确认后放行（写审计），`reject` 直接拒绝 | `warn` |

示例见 `deploy/config.toml.example`。

未知段、未知键、重复键、端口越界、类型不符都会直接报错并带上文件名与行号，例如：

```
启动失败: /etc/xiaotu/config.toml 第 4 行：未知配置项：server.portx
```

这样拼错配置不会静默失效。

## 3. 优先级

命令行 > 环境变量 > `config.toml` > 内置默认。

| 配置项 | 命令行 | 环境变量 | 配置文件 | 默认 |
| --- | --- | --- | --- | --- |
| 监听地址 | `--listen` | — | `server.listen` | `0.0.0.0` |
| 端口 | `--port` | — | `server.port` | `8080` |
| 数据目录 | `--data` | — | `storage.data_dir` | 系统应用数据目录 |
| 备份目录 | — | — | `storage.backup_dir` | `<数据目录>/backups` |
| 日志级别 | — | `XIAOTU_LOG_LEVEL` | `log.level` | `info` |
| 日志目录 | — | `XIAOTU_LOG_DIR` | `log.dir` | `<数据目录>/logs` |
| 信用额度超额行为 | — | — | `sales.credit_limit_mode` | `warn` |
| 配置文件 | `--config` | `XIAOTU_CONFIG` | — | `<数据目录>/config.toml` |

启动时输出的前几行会打印实际生效的配置来源，便于核对：

```
配置:     /etc/xiaotu/config.toml（已加载）
数据目录: /var/lib/xiaotu
数据库:   /var/lib/xiaotu/app.db
日志:     /var/log/xiaotu 级别 INFO
监听:     0.0.0.0:8080
```

## 4. 首次部署（Linux + systemd）

```bash
# 1. 系统账号与目录
sudo useradd --system --home /opt/xiaotu --shell /usr/sbin/nologin xiaotu
sudo install -d -o xiaotu -g xiaotu /opt/xiaotu /var/lib/xiaotu /var/log/xiaotu /etc/xiaotu

# 2. 二进制与配置
sudo install -o xiaotu -g xiaotu -m 0755 xiaotu-server /opt/xiaotu/xiaotu-server
sudo install -o root -g xiaotu -m 0640 deploy/config.toml.example /etc/xiaotu/config.toml

# 3. 首次设置管理员口令（同时完成建库与迁移）
sudo -u xiaotu env XIAOTU_PASSWORD='换成强口令' \
  /opt/xiaotu/xiaotu-server --config /etc/xiaotu/config.toml --set-password admin

# 4. systemd
sudo install -m 0644 deploy/systemd/xiaotu.service /etc/systemd/system/xiaotu.service
sudo systemctl daemon-reload
sudo systemctl enable --now xiaotu

# 5. 验证
curl http://127.0.0.1:8080/api/health
sudo journalctl -u xiaotu -n 30 --no-pager
```

`/api/health` 返回 `"status":"ok"` 和 `schema_version`，端口/监听以配置为准。

`xiaotu.service` 里已经带了 `ProtectSystem=strict`、`ProtectHome=yes`、`NoNewPrivileges=yes`，只放行 `/var/lib/xiaotu` 与 `/var/log/xiaotu` 写权限；改路径时同步改 `ReadWritePaths`。

## 5. 常用变更

改端口或监听地址：

```bash
sudo vi /etc/xiaotu/config.toml     # 改 server.port / server.listen
sudo systemctl restart xiaotu
curl http://<地址>:<端口>/api/health
```

临时覆盖日志级别（不改文件，重启后失效）：

```bash
sudo systemctl set-environment XIAOTU_LOG_LEVEL=debug
sudo systemctl restart xiaotu
```

数据和日志换盘（会话表在数据库文件里，连同 `app.db` 一起复制过去，用户不会掉线）：

```bash
sudo systemctl stop xiaotu
sudo cp -a /var/lib/xiaotu /newdisk/xiaotu
sudo chown -R xiaotu:xiaotu /newdisk/xiaotu
sudo vi /etc/xiaotu/config.toml     # storage.data_dir = "/newdisk/xiaotu"
sudo systemctl start xiaotu
```

如果新目录里是空库（而不是复制过去的旧库），所有人需要重新登录；恢复某份备份时，会话也回到那份备份里的状态。

多实例：不同 `storage.data_dir`、不同 `server.port`，各起一个进程即可（SQLite 单文件数据库不支持多进程同时写同一个库）。同一个数据目录已有进程持有时，新进程会提示持有者 PID 后退出（锁文件 `<数据目录>/app.lock`）；`--backup` 与 `--set-password` 不参与该锁。

数据目录**不要放在 iCloud Drive、OneDrive 等同步目录**。程序启动时会检测并打印告警，同时写入日志、在界面顶部显示提示；检测到后请尽快把目录迁到本地磁盘，迁移前先停服。

## 6. 备份与恢复

- **升级前自动备份**：启动时若发现库版本低于程序目标版本，先写 `<备份目录>/app-<时间>-pre-v<旧版本>.db`，再执行迁移。
- **手动备份**：`--backup`，生成 `<备份目录>/app-<时间>-manual.db` 后退出。备份用 `VACUUM INTO`，并做 `PRAGMA integrity_check`，运行中也能安全执行。

```bash
# 每天 02:00 备份
0 2 * * * /opt/xiaotu/xiaotu-server --config /etc/xiaotu/config.toml --backup
```

- **恢复**：停服 → `--restore <备份文件>` → 启动。恢复前会先把当前库另存为安全备份，不会直接覆盖丢失现场。

- **备份位置**：默认 `<数据目录>/backups/`，可用 `[storage] backup_dir` 单独指定（空串 = 默认；相对路径按数据目录解析；绝对路径原样使用）。备份与库同盘是最脆弱的位置，同一块盘坏了会一起丢失。
  - 建议把 `backup_dir` 指到独立数据盘（如单独挂载到 `/var/lib/xiaotu-backups`），或按下面的方式把默认目录 `rsync` 到另一块物理盘 / NAS；不要用 iCloud/OneDrive 等同步盘。
  - 目录不可写（权限不足、只读挂载、磁盘满）时备份会明确报 `BACKUP_DIR_UNWRITABLE` 并中止本次备份，不会静默改回默认目录。
  - 备份不加密（见 `docs/待决策清单.md` 第 20 条）；加密不能替代异地，同机持有密钥的人仍能解密。

```bash
sudo systemctl stop xiaotu
sudo -u xiaotu /opt/xiaotu/xiaotu-server --config /etc/xiaotu/config.toml \
  --restore /var/lib/xiaotu/backups/app-20261112-020000-manual.db
sudo systemctl start xiaotu
```

恢复出来的是备份时的结构版本，下次启动会自动迁移到当前版本，并按上一条再留一份迁移前备份。

## 7. 升级步骤

1. 停服前先手动备份一次，或确认自动备份可用。
2. `sudo systemctl stop xiaotu`，保留旧二进制（例如 `xiaotu-server.old`）便于回滚。
3. 用新二进制替换 `/opt/xiaotu/xiaotu-server`。
4. `sudo systemctl start xiaotu`，启动输出里确认两行：`迁移前备份: ...` 与 `数据库结构版本: vN`。
5. `curl /api/health` 看 `schema_version`，再抽查一张单据或报表。

回滚：停服 → `--restore` 迁移前备份 → 换回旧二进制 → 启动。数据库迁移是纯增量的，但旧程序不认识新表，回滚必须连库一起回退。

## 8. 日志

- 位置：`log.dir`（默认 `<数据目录>/logs`）下的 `app.log`，单文件 5MB，滚动保留 `app.log.1`–`app.log.3`。
- systemd 下标准输出/错误同时进 journal：`journalctl -u xiaotu -f`。
- 记录内容：启动参数摘要、迁移与备份、监听地址、登录失败、请求错误；**不记录**口令、Cookie、请求体。
- 排查顺序：`grep ERROR app.log` → 看是否端口占用（`bind` 失败）→ 登录返回 429 说明触发了 5 分钟 5 次的登录限流。

## 9. 已知行为

- 会话保存在数据库的 `app_session` 表：**重启服务后用户不需要重新登录**。空闲 30 分钟滑动续期，同时有绝对 12 小时上限（按 `created_at` 计算）；两个值可在「系统参数」页调整。登出、改密、用户停用或删除都会立即失效；过期记录在启动时和每次登录成功后清理。表里只存令牌散列，不存明文令牌。
- 换数据目录或恢复别的备份时会话回到那个库的状态：数据目录换成空库、或恢复到较早的备份，相关用户需要重新登录。升级时原地迁移不换库，会话保留。
- 口令用 Argon2id 存储；网络版禁用一次性 token 登录。
- 前面挂 HTTPS 反向代理时，转发头带 `X-Forwarded-Proto: https`，会话 Cookie 会自动加 `Secure`。
- macOS / Windows 没有 systemd：macOS 可用 `launchd`，Windows 可用「服务」或计划任务包装 `xiaotu-server.exe --server`；本文只覆盖 Linux。

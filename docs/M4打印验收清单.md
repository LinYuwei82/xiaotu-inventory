**真机做法**

1. 样张：241×140 采购明细（12 列）、241×93 销售出库单据各一份；另打一张 10 mm 网格校准页。
2. 测点：每张量左上首行首列、右上首行末列、左下末行、右下末行四处，用钢尺或游标卡尺读到 0.5 mm。
3. 套打：把打印样张与空白表格纸对齐（透光或针孔对齐），记录四个测点相对模板坐标的偏移，正负都记。
4. 连续走纸：同一单据连打 20 张，每张量首行位置；比较第 1 张与第 20 张的偏移差，记录是否卡纸、跑纸。
5. 复写：用 3 联复写纸打同一张，检查第 3 联；拍照留证。
6. 记录：每张样张拍照，偏移数据填表（测点 / 第几张 / X 偏移 / Y 偏移），失败项附打印机型号、驱动、纸张规格。

**放行规则**：三项全部满足才算真机通过；任一不满足不得对外声明「针式打印已验收」。

实测到的两条渲染行为：

1. WKWebView 打印时忽略 `NSPrintInfo` 的四边 margin 和居中设置；前端在原生模式下又把 `@page margin` 设为 0（`web/app.js` 479–480 行），叠加后 PDF 边距为 0。
2. WKWebView 对整页施加隐式缩放：基线 1.067 倍（CSS 10pt → PDF 10.68pt）；整页宽度超过纸宽时再整体缩到纸宽（241×140 采购明细为 1.067 × 0.896 ≈ 0.955）。

规则说明（服务端 `plan_print_layout`）：

- 单页纸默认「按纸宽自适应」，只缩版式（CSS `zoom`），不改数值；缩放后有效字号低于 7pt 时返回 `font_too_small`。

- 「期望起点」= `margin_mm` + 该列之前所有模板列宽之和 × `layout.scale_percent`；这是模板与 `layout` 共同定义的期望值。

### 4. 本次发现的两个链路阻塞（事实记录）

1. **报表打印 URL 拼接（已修）**：`periodQuery()` 返回以 `?` 开头的串，旧代码把它直接拼在 `target_key=...` 后，服务端返回「未知的打印目标」。现已统一用 `withQuery`（`URL` + `URLSearchParams`）构造查询串（`web/app.js` 789–795 行），四个打印入口用真实请求确认不再返回该错误。
2. **`runOperation` 空白页（代码层已修）**：同一台机器、同一 WKWebView、同一 `NSPrintInfo` 下，`runOperation` 产出大量空白页，`runOperationModalForWindow` 生成 1 页有效 PDF。应用内导出已改走窗口模态会话（`shell/mac/webview.mm` 301–309 行）；Cmd+P 的交互式打印仍走 `runOperation`。导出路径尚未在真实应用窗口复测。
3. **系统页眉页脚（代码层已修）**：打印预览顶部的「日期 + 小兔进销存」来自 AppKit 的 `NSPrintHeaderAndFooter`，不是模板内容；`document.title` 是「小兔进销存」，日期由系统格式化。已在 `XiaotuApplyPaper` 中对 `NSPrintInfo` 显式设置 `NSPrintHeaderAndFooter=NO`，系统打印与导出 PDF 共用，所有打印目标一起生效；模板自己的 `company_name`/`header_text` 不受影响。关闭的是页边距内的页眉，正文起点与模板 `@page margin` 不变。网络版浏览器打印无法代码控制，需在打印对话框取消「页眉和页脚」（已写入用户手册）。

## 六、页码能力实测（2026-11-13）

**环境与方法**

- macOS 15.8.2；独立 AppKit + WKWebView + PDFKit 探针，A4、`margin: 12mm`，HTML 内容 3 页。
- 打印链路：`[WKWebView printOperationWithPrintInfo:]` + `NSPrintSaveJob`（`showsPrintPanel = NO`），PDF 文本用 PDFKit 回读。
- 对照两种写法：`@page { @bottom-right { content: "第 " counter(page) " 页" } }`；以及 `position: fixed; bottom: 0` 的页脚 + `::after { content: "第 " counter(page) " 页" }`。

**结果**

| 写法 | 页数 | 页码结果 |
| --- | --- | --- |
| `@bottom-right` margin box | 3 | 3 页均只有正文，页码出现 0 次 |
| `createPDF`（同一 HTML） | 1 | 单页连续快照，页码不渲染 |
| `position: fixed` 页脚 + `counter(page)` | 3 | 页脚只在末页出现，解析为「第 0 页」；前两页无页脚 |

**结论**

- WKWebView 打印不渲染 `@page` 的 margin box，也不支持 `counter(page)`；`position: fixed` 元素在打印分页中不会逐页重复。
- 因此 `show_page_no` 在 WKWebView 不生效；「HTML 固定页脚」兜底同样不成立。按最小方案落地（2026-11-13）：保留 `show_page_no` 作为提示性字段，不做前端显式分页、不做 PDF 后处理叠页码；模板编辑处提示「页码随打印引擎而定；网络版可在浏览器打印对话框勾选页眉和页脚」。
- 本结论只覆盖上述探针环境；浏览器打印（Safari / Chrome / Firefox）的 margin box 支持各不相同，未逐一实测。

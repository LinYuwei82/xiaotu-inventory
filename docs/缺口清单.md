### 2.10 Windows 壳接入顶层构建（部分实现）

- 现状：根 `CMakeLists.txt` 第 71–80 行已有 `XIAOTU_BUILD_WIN_SHELL`（默认 OFF、仅 `WIN32` 生效、非 Windows 警告并忽略），`shell/win/CMakeLists.txt` 被 `add_subdirectory` 引入时跳过 `project()`。默认配置不产生壳目标、不引入 WebView2。

## 五、建议优先级

### 交付前必须完成

1. **针式打印真机验收与页码方案定稿**（4.8、Q12）：目标客户若使用针式打印机，这是验收硬门槛；页码需先确认 WKWebView 是否支持，再决定 HTML 页脚方案。
2. **软件更新链路**（6.8、Q23–Q26）：至少完成 macOS 侧，否则发布后无法修复线上问题；Windows 可先手动下载过渡。
3. **签名与公证**（7.1、Q20–Q22）：对外分发的前置条件；需先取得 Developer ID 证书。
4. **partner 统一收口**（2.1）：避免新建客户在单据与信用额度上出现两套数据，越晚迁移成本越高。
5. **成本调整单**（2.2 的替代路径）：不做重算写回，差异靠成本调整单落地，影响账实一致与毛利报表可信度。
6. **前端离线提示**（6.3）：网络版在断网、休眠、服务重启时缺少可用反馈，属基础体验。
7. **恢复成功审计**（1.4）：恢复是高风险操作，至少保证可追溯，不依赖完整向导。

### 可延后

- 单据幂等与乐观锁（1.3）：单机与小团队风险低；网络版多人并发上量前完成即可。
- 报表导出流式化（2.3）：十万行以内可用，数据规模上来前不阻塞。
- 多单位、批次、数据权限、License、外部对接（Q4、Q5、Q17–Q19）：按目标客户与首发范围决定。
- Windows 安装包与签名（2.7）：若首发仅 macOS，可延后。
- 6.9 其余额度执行（2.5）：当前社区版仅单用户，额度控制优先级低。
- 物理删除与同步目录拒绝写入（2.8、2.9）：软删与告警已可接受。
- 恢复向导 UI（1.4）：CLI 可用时优先保证审计与文档指引。

# 主数据导入导出方案（商品 / 供应商 / 客户）

> 历史归档：本文是主数据导入导出的设计记录，命令、路径与代码行为可能已过时，勿照做；当前实现以代码与 `README.md` 为准。
>
> 状态：**已定：A（按编码 upsert）**，已实现并上线。导入只收真 xlsx，导出保留 xlsx / csv；
> 每次导入写库前自动 `VACUUM INTO` 备份，备份失败即中止。

## 1. 现状盘点

### 1.1 现有导出是真的 xlsx

`server/src/xlsx.cpp` 自己拼 ZIP + XML，不依赖第三方库：

- ZIP 用 store（不压缩）方式写入，CRC32 自算；
- 工作表使用 `inlineStr` 写文本，不生成 `sharedStrings.xml`；
- 只有单工作表，表头加粗、金额单元格走 `0.00` 数字格式；
- 响应头是 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`。

所以现有 `.xlsx` 是**真正的 xlsx**，不是改扩展名的 CSV。Excel、Numbers、WPS 都能直接打开。

CSV 导出则是另一条路径：`\xEF\xBB\xBF` 开头（UTF-8 BOM），`text/csv; charset=utf-8`，字段按 RFC4180 加引号。

### 1.2 报表导出的表头不适合直接喂给导入

现有报表的 CSV / xlsx 在表头前有 4 行说明（报表名、筛选条件、导出时间、金额说明），第 5 行空行，之后才是列头。这套格式是给人看的报表，不是给程序读的数据表。

主数据导出要单独出一份「干净」的表：第 1 行列头，第 2 行起是数据，不加任何前言。这样导出的文件可以直接改完再导回来，做备份/恢复闭环。

### 1.3 三类主数据的现状

| 表 | 列表页 | 新增/编辑 | 删除 | 权限点 | 编码字段 |
| --- | --- | --- | --- | --- | --- |
| 商品 `item` | 有 | 有 | 有 | `item.read` / `item.write` | 有，唯一 |
| 供应商 `supplier` | 有 | 有 | 有 | `supplier.read` / `supplier.write` | 有，唯一 |
| 客户 `customer` | 有 | 有 | 有 | `customer.read` / `customer.write` | 有，唯一 |

三张表的页面都是代码生成器产出的（`pages.json` + `page.js.j2`），列表页已增加
「下载模板 / 导出 Excel / 导出 CSV / 导入」入口；模板与导出都带权限判断，
导入按钮只对 `*.write` 可见。

导入完成后建议提供「导出当前全部」做备份：按实体各导一个文件（单工作表），不合并成一个多 Sheet 工作簿——现有 `XlsxSheet` 只支持单表，做多 Sheet 要改 workbook 关系文件，收益不大。

## 2. 导入格式：xlsx 与 CSV 的取舍

### 2.1 真 xlsx

用户从 Excel「另存为 .xlsx」得到的文件是 **deflate 压缩的 ZIP**，当前导出器只会 store 写入，读不了。要读必须有一份 inflate 实现。

可选做法：

1. 引入 `miniz`（单文件/双文件、public domain、macOS 与 MSVC 都能直接编）。只编 inflate 时可以关掉 deflate API，源码量与产物增加都很小（源码约 150KB，编进二进制大概几十 KB）。
2. 自己写 inflate。不推荐，边界情况多，测试成本远高于引入 miniz。

解析部分只需三样东西：`xl/workbook.xml`（找到第一个 sheet 的关系）、`xl/worksheets/sheet1.xml`、`xl/sharedStrings.xml`。主数据全是文本、整数、布尔，不涉及日期序列号和公式，解析面很窄。列按**表头文字**匹配，不依赖列顺序。

代价：

- `third_party/` 多一个依赖，需要在 CMake 里给 core/server 都加上；
- 需要处理 Excel 的几种写法：共享字符串、inlineStr、空单元格、合并单元格（表头一般不会合并，遇到就报错而不是猜）；
- 需要新增单元测试样本（真 Excel 存出来的文件，不能只用自己导出的文件测，因为自己导出的是 store + inlineStr，恰好绕开了共享字符串和 deflate）。

收益：中文不乱码、不会出现「打开 CSV 双击变乱码」「Excel 保存后编码变成 GBK」这类问题，用户不需要理解编码。

### 2.2 CSV（UTF-8 带 BOM）

实现成本低：按引号规则拆行即可，不需要新依赖。

坑在 Excel：

- 只有「CSV UTF-8（逗号分隔）」才会保留 BOM 和 UTF-8；中文 Windows 上用户很容易选成普通「CSV（逗号分隔）」，保存出来是 GBK/GB18030，服务端按 UTF-8 读就是乱码；
- 要兼容 GBK 就得再引一份编码转换（iconv 在 macOS 可用，Windows 需要额外处理），复杂度反而超过 xlsx；
- 单元格里带换行、逗号、引号时，手改容易破坏格式；
- 数字编码会被 Excel 吃掉前导零（比如 `001` 变 `1`）。

### 2.3 推荐

**导入只支持 `.xlsx`，导出同时保留 `.xlsx` 与 `.csv`。**

- 导入走 xlsx，避开编码问题，和用户「Excel 表」的预期一致；
- 导出保留 CSV，是因为报表页已经有 CSV，且部分用户习惯用 CSV 做二次处理；
- 不为导入单独做 CSV 兼容。若以后确有需要，再加「CSV UTF-8」入口，并在页面写明必须选「CSV UTF-8」。

只读不写：miniz 只编 inflate，xlsx 写入继续用现有 `XlsxSheet`，两边互不影响。

## 3. 列定义

列名用中文，第 1 行列头，顺序可以调整，导入按列头匹配；不认识的列忽略并在结果里提示「已忽略未知列」。

### 3.1 商品

| 列名 | 必填 | 说明 |
| --- | --- | --- |
| 商品编码 | 是 | 唯一；建议在 Excel 里设为文本格式，避免前导零丢失 |
| 商品名称 | 是 | 允许重名（数据库本身不唯一）；已有商品留空表示不改名 |
| 规格 | 否 | 自由文本；空表示保持原值 |
| 计量单位 | 是 | 按**单位名称**匹配 `unit.name`，名称重名时可改填单位编码；新增商品必填 |
| 启用 | 否 | 是/否；空表示保持原值（新增行按系统默认「启用」） |

说明：

- 单位不用编码匹配，是因为这张表给业务人员填，记编码不现实；但 `unit.name` 目前**不是唯一索引**，如果出现重名单位，导入报「单位名称不唯一，请改为填写单位编码」，不会随便挑一个。
- 「单位」这个旧字段是 `unit.name` 的同步值，导入只填 `unit_id`，由服务层同步名称，不单独接受一列「单位」。
- 不导入 `id`、创建时间等系统字段。

### 3.2 供应商 / 客户

两张表结构一致：

| 列名 | 必填 | 说明 |
| --- | --- | --- |
| 编码 | 是 | 唯一 |
| 名称 | 是 | 允许重名；已有档案留空表示不改名 |
| 联系人 | 否 | 空表示保持原值 |
| 电话 | 否 | 按文本处理，避免被 Excel 当数字；空表示保持原值 |
| 地址 | 否 | 空表示保持原值 |
| 启用 | 否 | 是/否；空表示保持原值（新增行按系统默认「启用」） |

布尔解析统一接受：`是/否`、`1/0`、`TRUE/FALSE`、`启用/停用`；其他值报错，不做模糊猜测。

## 4. 校验与报错

采用**先全量校验、再备份、再一次性写入**：

1. 解析文件，按表头映射列；表头不认识、重复或缺少必填列直接拒绝整个文件；
2. 逐行校验：必填、布尔值、单位是否存在且唯一、表内编码是否重复、编码是否已被已删除档案占用；
3. 收集**全部**错误，不做「遇错即停」——用户一次能看到所有问题，不用改一处传一次；
4. 有任何错误：返回 400，不写库、也不产生备份；
5. 全部通过：先做一次 `VACUUM INTO` 备份（目录 `<数据目录>/backups`，文件名带 `pre-import-<表>`）；
   备份失败立即中止，绝不「先导了再说」；
6. 备份成功后，在**一个事务**里写入，提交后返回成功条数。

错误结构：

```json
{
  "ok": false,
  "code": "IMPORT_INVALID",
  "message": "共 3 行有问题，未导入任何数据",
  "errors": [
    {"row": 2, "column": "商品编码", "reason": "不能为空"},
    {"row": 5, "column": "计量单位", "reason": "单位「箱」不存在"},
    {"row": 9, "column": "商品编码", "reason": "与第 4 行重复"}
  ]
}
```

前端：

- 页内对话框展示前 100 条，标注「第 N 行 / 列名 / 原因」；
- 提供「下载错误清单」，直接由前端把收到的错误数组生成 UTF-8 带 BOM 的 CSV（行号、列名、原因），不额外落库；
- 错误行号按 Excel 实际行号（表头是第 1 行，数据从第 2 行开始），不按数组下标。

部分成功 vs 全量回滚：**全量回滚**。主数据导入最怕导一半，后续单据引用了半截资料，清理起来比重新导一次麻烦得多。

## 5. 重复数据策略（已定：A）

**按编码 upsert**：

- 编码已存在：只更新表里**非空**的单元格；空单元格一律保持原值，包括「启用」。
- 编码不存在：新增；新增行的空单元格按系统默认（规格/联系人等为空，「启用」为是）。
- 表内同一编码出现两次：直接报错「与第 N 行重复」，整批不导入，不做后者覆盖前者。
- 商品允许同名不同编码，导入不按名称判重；供应商/客户按编码唯一。
- 编码若只被一条**已删除**档案占用（唯一索引仍占位），报「编码已被已删除的档案占用，请改用其它编码」，
  不静默恢复也不覆盖。

空单元格口径（写进页面提示与用户手册）：

> 空单元格表示「这一格不动」，不是清空。已有档案的「启用」留空不会把档案改成启用，
> 也不会把已停用的档案重新启用；要改状态请明确填「是」或「否」。

风险（接受 A 的前提）：

- 用户拿旧表导回来，会把线上改过的名称/电话覆盖回旧值——所以每次写库前强制备份；
- 导入期间别人正在编辑同一条记录，后提交的覆盖先提交的；单机/小团队场景接受该窗口。

## 6. 事务与规模

- 一个导入请求一个 `BEGIN IMMEDIATE` 事务，所有行在同一次提交里完成；任何一行失败整体回滚。
- 不要逐行调用现有 `ItemService::create/update`：每个方法内部各自开事务、各写一条审计，1000 行会变成 1000 次提交，既慢又留下半截审计。导入走独立服务，复用 DAO 的 insert/update，事务外做完全量校验。
- 审计只写一条：`import`、实体类型、成功条数、文件名，避免审计表被批量导入刷屏。
- 规模上限：单次 5000 行、文件 5MB。超过直接拒绝并提示分批。
- 请求体：httplib 的 `set_payload_max_length` 是全局设置，当前放宽到 5MB 供原始二进制上传；
  pre-routing 里再按 `Content-Length` 把**非 `/import` 路径**限制回 1MB，不会把其它接口一起放大。
- xlsx 用原始二进制上传，不转 base64，避免体积膨胀。
- 同步处理即可：5000 行在单事务内是毫秒到百毫秒级，不需要后台任务；导入期间写锁只覆盖这一次事务，WAL 下其他读不受影响。
- 前端上传时禁用按钮并显示「导入中…」，避免用户连点造成重复导入。

## 7. 权限

沿用现有权限点，不新增：

- 商品导入/导出：`item.write` / `item.read`
- 供应商：`supplier.write` / `supplier.read`
- 客户：`customer.write` / `customer.read`

规则：

- 「导入」按钮只对 `*.write` 可见，服务端接口同样用 `guard("item.write", ...)` 兜底；
- 「下载模板」「导出当前全部」只需要 `*.read`；
- 写接口沿用现有 CSRF 校验。

3. **供应商、客户**：复用同一框架接入两张表，页面入口与权限对齐。
4. **错误清单与导出收尾**：错误清单下载、未知列提示、行数/文件大小上限提示，补导入冒烟用例（含失败回滚、重复编码、单位不存在）。
5. **文档与手册**：README 接口说明、用户手册补「批量导入」一节（写清编码必须文本格式、失败不落库、上限）。

# 发布前检查清单

只用于发布执行时逐项确认，不在平时自动运行。未完成项不得出包。

## 1. 版本与代码

- [ ] 仓库根 `VERSION` 已改为本次发布版本，且 `CMakeLists.txt` 与两个壳均从该文件取值（macOS 的更新与恢复按 `version` 判定，v2 清单 `platforms.macos.build` 固定 `0`，只加构建号、不升 `VERSION` 会导致 macOS 客户端无更新）
- [ ] `XIAOTU_BUILD` 已设为本次构建号（单调递增），`XIAOTU_API_VERSION` 未意外变更
- [ ] `tools/codegen/.venv/bin/python tools/codegen/generate.py --check` 通过
- [ ] 工作区干净，提交已推送，tag 指向发布提交

## 2. 构建与测试

- [ ] `cmake --preset macos-release && cmake --build --preset release`
- [ ] `ctest --test-dir build/release --output-on-failure` 全绿
- [ ] `cmake --preset macos-community && cmake --build --preset community`
- [ ] `ctest --test-dir build/community --output-on-failure` 全绿
- [ ] `tools/ci/check.sh` 完整通过（含 Windows 交叉构建与平台泄漏检查）
- [ ] 空库迁移到最新 schema 无报错；从上一发布版本升级无 checksum 报错

## 3. macOS 签名与公证

- [ ] 本机 `security find-identity -v -p codesigning` 能看到 Developer ID Application 证书
- [ ] `XIAOTU_SIGN_IDENTITY` 指向正确证书，`tools/package/make_dmg.sh` 输出「使用证书」
- [ ] `XIAOTU_NOTARY_PROFILE` 已配置，脚本输出「已公证」而非「跳过」
- [ ] `codesign --verify --deep --strict` 与 `spctl --assess` 均通过
- [ ] `xcrun stapler validate` 对 dmg 通过

## 4. 包体与哈希

- [ ] dmg 文件名包含版本号，体积与上一版无异常波动
- [ ] dmg 内 `.app` 的 `CFBundleShortVersionString` 等于 `VERSION`，`CFBundleVersion` 等于 `XIAOTU_BUILD`
- [ ] 已记录 SHA256，并写入发布说明
- [ ] 安装到干净机器后首次启动不被 Gatekeeper 拦截

## 5. Windows

- [ ] `shell/win/fetch-webview2.ps1` 成功，SDK 版本已记录
- [ ] `packaging\win\build-release.cmd <构建号>` 一键出包通过（setup.exe + portable.zip）
- [ ] 目标机器已安装 WebView2 Runtime
- [ ] 安装包（Inno Setup）已生成；本地产物未签名，如用 CI 产物需核对 `SIGNING.txt` 与实际签名状态一致
- [ ] 服务端与壳用同一个 `XIAOTU_BUILD` 构建（`build/windows/build.ninja` 与 `shell/win/build/build.ninja` 的 `DEFINES` 一致，不能是默认值或 0）
- [ ] 在 Mac 上执行 `BUILD=<构建号> tools/package/publish_windows.sh`，`manifest.json` 的 `platforms.windows` 已合并上传到 `xiaotu/updates/stable/manifest.json` 并验签通过
- [ ] 仓库有 `docs/release-notes-<版本>.html` 时会自动上传并写入清单 `notes_url`；确认该地址可打开，客户端「查看更新详情」正常
- [ ] 已发版本补/改说明页用 `NOTES_ONLY=true tools/package/publish_oss.sh`（或 `publish_windows.sh`），不要重出包；完成后核对清单 `updated_at` 已变化、`version` 与产物 size/sha256 未变
- [ ] `xiaotu-shell.exe` 与 `xiaotu-server.exe` 同目录运行，能拉起窗口
- [ ] 在干净 Windows 机器上实测安装 + 启动（SmartScreen 手动放行后正常）
- [ ] 发版 Checklist 逐条核对 `docs/未签名分发注意事项.md`，客户说明 `docs/客户安装说明.md` 已随包发出

## 6. 发布前冒烟

- [ ] 单机版：启动、登录、主数据、单据、报表、打印/导出 PDF、审计、诊断
- [ ] 网络版：`--server` 启动、登录、权限校验、导出、打印（浏览器）、备份
- [ ] 版本号在「关于/诊断」、`/api/health`、`.app` 信息三处一致
- [ ] 升级路径：旧版本数据目录直接启动新版本，迁移成功且数据可读
- [ ] 更新清单指向 stable，客户端能检查到新版本且不强制安装

## 7. 回滚预案

- [ ] 发布前对生产数据目录做一次完整备份，并验证可恢复
- [ ] 保留上一版本安装包与更新清单副本
- [ ] 确认回滚步骤：停服 → 还原数据备份 → 装回旧版本 → 更新清单回退
- [ ] 回滚后检查 schema 版本、登录、单据与报表抽查

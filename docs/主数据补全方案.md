# 主数据补全与期初导入方案

当前数据库结构版本：v16。本文覆盖四项：商品分类/条码/税率、职员档案与业务员、客户供应商税号与信用额度、期初导入。
只给设计与拆分，不含实现。已由用户拍定的口径直接按定稿写，只有真正会影响后续、改起来代价高的点留在第 9 节。

## 0. 已定口径摘要

| 项 | 结论 |
| --- | --- |
| 税率存储 | `tax_rate_bp INTEGER NOT NULL DEFAULT 0`，整数万分比；`1300`=13%，`150`=1.5%，`0`=不计税/免税 |
| 税额计算 | 全程整数：`round_half_up(金额 × tax_rate_bp / 10000)`，只在最终金额上取整一次；显示时才除 10000；与 `mul_qty_price`、4 位定点数量共用同一套取整规则 |
| 商品分类结构 | `item_category.parent_id` 自引用 + `path` 冗余（`/1/7/23/`），按分类查商品用 `path` 前缀匹配带出整棵子树，不递归 |
| 分类层数 | 数据库不限层数；产品约定三层，录入界面在第三层之下不再提供「新建子分类」 |
| 停用分类 | 不出现在新建商品下拉；已归属的商品照常显示，仅做视觉标注 |
| 信用额度控制点 | 销售出库审核（产生应收的那一刻），不在销售订单；只做客户侧 |
| 已占用口径 | 该客户未核销应收合计（`ar_ap_entry` 未结清部分）+ 本次出库金额，与 `credit_limit_cents` 比较 |
| 超额默认行为 | 提示不拦：二次确认后可继续，写审计日志（客户、额度、已占用、本次金额、超出额）；配置开关可切「拒绝」 |
| 期初范围 | 库存、应收、应付、资金账户四类；主数据档案导入已有，不并入；在途、暂估不做 |
| 库存期初 | 走真实单据「其他入库 + 期初类别」，审核后进流水与结存，可反审核、参与成本重算；成本单价必填 |
| 应收应付期初 | 直接写 `ar_ap_entry` 并打期初标记，走现有核销，不生成业务单据 |
| 资金账户期初 | 用账户已有的 `opening_cents`，不另建记录 |
| 期初导入门槛 | 有业务流水之后一律拒绝，不做覆盖或追加；重来必须清空重建 |

## 1. 商品分类、条码、税率

### 1.1 表与列

```sql
-- v17：商品主数据扩展（分类 + 条码 + 税率）
CREATE TABLE item_category (
  id         INTEGER PRIMARY KEY,
  parent_id  INTEGER NOT NULL DEFAULT 0,          -- 0 表示根
  name       TEXT    NOT NULL,
  path       TEXT    NOT NULL,                    -- 形如 /1/7/23/
  sort_order INTEGER NOT NULL DEFAULT 0,
  status     INTEGER NOT NULL DEFAULT 1,          -- 1 启用 / 0 停用
  is_deleted INTEGER NOT NULL DEFAULT 0,
  created_at TEXT    NOT NULL,
  created_by TEXT    NOT NULL DEFAULT 'system',
  updated_at TEXT    NOT NULL,
  updated_by TEXT    NOT NULL DEFAULT 'system',
  CHECK (status IN (0, 1)),
  CHECK (is_deleted IN (0, 1))
);
CREATE UNIQUE INDEX uk_item_category_sibling ON item_category(parent_id, name);
CREATE INDEX idx_item_category_path ON item_category(path);

ALTER TABLE item ADD COLUMN category_id INTEGER NOT NULL DEFAULT 0;   -- 0 = 未分类
ALTER TABLE item ADD COLUMN tax_rate_bp INTEGER NOT NULL DEFAULT 0;   -- 万分比

CREATE TABLE item_barcode (
  id         INTEGER PRIMARY KEY,
  item_id    INTEGER NOT NULL REFERENCES item(id),
  barcode    TEXT    NOT NULL,
  is_primary INTEGER NOT NULL DEFAULT 0,
  created_at TEXT    NOT NULL,
  CHECK (is_primary IN (0, 1))
);
CREATE UNIQUE INDEX uk_item_barcode ON item_barcode(barcode);
CREATE INDEX idx_item_barcode_item ON item_barcode(item_id);
```

- `path` 由服务层维护：新建时 `父.path + 新 id + '/'`；移动分类时整棵子树前缀替换。删除分类为软删除，带商品或子分类时拒绝。
- 分类查询商品：`item.category_id IN (SELECT id FROM item_category WHERE path LIKE '/1/7/%')`，命中整棵子树，不递归。
- 同级重名：**推荐不允许**（`uk_item_category_sibling`），避免报表与导出出现无法区分的同名节点；跨级重名允许。列为待定项，见 9.4。
- 未分类：**推荐 `category_id = 0` 即「未分类」**，不自动建节点，报表把 0 归入「未分类」，不猜业务含义。列为待定项，见 9.3。

### 1.2 条码

- **推荐一个商品可多码**（`item_barcode`），条码全局唯一，`is_primary` 标记主码；主码同时回写一个只读展示字段不必落库，按 `is_primary` 取。列为待定项，见 9.5。
- 查询：条码精确匹配返回商品；扫描枪输入走同一接口。
- 若最终改成一商品一码，退化为 `item.barcode` 单列 + 唯一索引，前端与查询逻辑不变；因此先按多码设计，不影响后续收敛。
- **当前状态（截至 v21）：一商品多码未实施。** 实际可用的是 `item.barcode` 单列（一商品一码，全局唯一，空串可重复）；`item_barcode` 表只是预留，代码不写入；v21 仅把该表的 `item_id` 唯一索引改为普通索引，为将来多码留位，不代表多码已可用。

### 1.3 税率

- 商品级 `item.tax_rate_bp` 作为默认值；单据行覆盖形式见第 9 节待定项。
- 税额只在汇总/开票口径计算，库存成本与现有 `doc_line.amount_cents` 不因税率改变。
- 展示：`bp / 100` 得百分数（`1300 → 13.00`），输入校验 `0 ≤ bp ≤ 10000`。
- **当前状态：含税字段未实施。** 只存商品级税率并做展示与导入导出；没有单据行税率覆盖，也没有 `price_includes_tax` 之类含税标记，税额未参与任何计算。

### 1.4 权限与接口

| 动作 | 接口 | 权限 |
| --- | --- | --- |
| 分类树读写 | `/api/item-categories` | `masterdata.category` 对应现有 `item.write` |
| 商品按分类/条码查 | `/api/items?category_id=&include_children=1&barcode=` | `item.read` |
| 条码维护 | 随商品详情提交 | `item.write` |

分类能力键 `masterdata.category` 已存在（社区版 full），不新增能力开关。

### 1.5 历史数据

- 现有商品 `category_id = 0`（未分类）、`tax_rate_bp = 0`（不计税）、无条码；不自动建分类、不猜测税率。
- 导入/导出模板新增「分类路径」「条码」「税率%」三列；分类路径不存在时按「先全量校验、整批不写」拒绝，避免半个树。

## 2. 职员档案与业务员字段

### 2.1 与 `app_user` 的关系

- **推荐两套人两张表**：`employee` 是业务档案（不限登录），`app_user` 是登录账号。理由：社区版 1 个账号、10 个职员，把两者合并会让「多人共用一套账」无法表达；且职员不需要口令与角色。列为待定项，见 9.6。
- 预留 `employee.user_id INTEGER NOT NULL DEFAULT 0`，非 0 时表示该职员绑定了登录账号，用于「当前登录人默认业务员」；本期不做绑定界面，字段先留。

```sql
-- v18：职员档案 + 单据业务员
CREATE TABLE employee (
  id         INTEGER PRIMARY KEY,
  code       TEXT    NOT NULL,
  name       TEXT    NOT NULL,
  phone      TEXT    NOT NULL DEFAULT '',
  department TEXT    NOT NULL DEFAULT '',
  position   TEXT    NOT NULL DEFAULT '',
  user_id    INTEGER NOT NULL DEFAULT 0,
  status     INTEGER NOT NULL DEFAULT 1,
  is_deleted INTEGER NOT NULL DEFAULT 0,
  created_at TEXT    NOT NULL,
  created_by TEXT    NOT NULL DEFAULT 'system',
  updated_at TEXT    NOT NULL,
  updated_by TEXT    NOT NULL DEFAULT 'system',
  CHECK (status IN (0, 1)),
  CHECK (is_deleted IN (0, 1))
);
CREATE UNIQUE INDEX uk_employee_code ON employee(code);

ALTER TABLE doc_header ADD COLUMN salesperson_id   INTEGER NOT NULL DEFAULT 0;
ALTER TABLE doc_header ADD COLUMN salesperson_name TEXT    NOT NULL DEFAULT '';
CREATE INDEX idx_doc_header_salesperson ON doc_header(salesperson_id, doc_date);
```

### 2.2 业务员字段的落点

- **单据表头**：一张单据一个业务员，符合提成与业绩归集的实际；明细行级会迫使每行校验一致，收益低。
- 适用单据：销售订单、销售出库、销售退货（`SAL_ORDER`/`SAL_OUT`/`SAL_RET`）；采购单据不设。
- 保存 `salesperson_name` 快照，档案改名不影响历史单据；停用/离职职员在报表中照常出现，仅视觉标注。
- 校验：`salesperson_id = 0` 允许（未指定），非 0 必须存在且未删除；`status = 0` 允许历史使用但新建时提示。

### 2.3 权限与历史数据

- 接口 `/api/employees`，权限 `employee.read` / `employee.write`（能力键 `masterdata.employee` 已存在）。
- 额度：社区版 10 人（`max_employees`），与登录账号额度独立。
- 历史单据 `salesperson_id = 0`、`salesperson_name = ''`；报表归入「未指定」，不回填。

## 3. 客户 / 供应商税号与信用额度

```sql
-- v19：往来单位税号与客户信用额度
ALTER TABLE supplier ADD COLUMN tax_no TEXT NOT NULL DEFAULT '';
ALTER TABLE customer ADD COLUMN tax_no TEXT NOT NULL DEFAULT '';
ALTER TABLE customer ADD COLUMN credit_limit_cents INTEGER NOT NULL DEFAULT 0;
```

- 税号只存文本，不做格式校验（各地税号规则不同）；导出/打印使用。
- 信用额度**只做客户**，供应商不加空字段。
- 额度为 `0` 视为**不限制**。理由：存量客户默认值都是 0，若视为零额度会把所有客户一刀切拦死；行业惯例也是 0=不限。
- 已占用不落缓存列，审核出库时实时汇总：
  `SUM(amount_cents - settled_cents) FROM ar_ap_entry WHERE partner_id=? AND direction=1 AND status IN ('OPEN','PARTIAL')`。
  撤销收付款、反审核、核销都会改变这张表，下一次审核自动重算，不需要额外路径。
- 比较时点：`SAL_OUT` 审核、生成应收之前；`SAL_RET` 冲减应收，不触发拦截。
- 超额行为：
  - 默认「提示不拦」：接口返回结构化错误码 `CREDIT_LIMIT_EXCEEDED` 与明细（客户、额度、已占用、本次金额、超出额），前端二次确认后带 `confirm_credit_overrun=1` 重提；
  - 开关切「拒绝」：同错误码直接拒绝；
  - 两种模式都写审计日志（现有审计表，动作 `credit.overrun`）。
- 开关落点：沿用现有配置方式（`config.toml`），键 `credit.overrun = "warn" | "reject"`，不新建参数表。
- 接口：客户/供应商读写接口新增 `tax_no`，客户新增 `credit_limit_cents`；主数据导入导出列同步增加。

## 4. 期初导入（四类）

统一约束：单事务、先全量校验、一行错整批不写；错误含行号 + 列名 + 原因；权限沿用现有导入权限（库存 `stock.write`、往来 `finance.write`、账户 `finance.write`）。

### 4.1 库存期初（无迁移）

- 走真实单据：按仓库生成一张 `OTH_IN`，`biz_category='OPENING'`，审核后进 `stock_ledger` 与 `stock_balance`，可反审核、参与成本重算（v16 已支持）。
- Excel 列：仓库编码、商品编码、数量、成本单价（元）。成本单价为空直接判错，不默认 0。
- 同一仓库同一商品多行时合计后导入；数量必须 > 0。
- 金额 = `round_half_up(qty × 单价)`，按整数分写入行金额，避免逐行浮点。

### 4.2 应收 / 应付期初（v20 迁移）

`ar_ap_entry` 当前 `uk_ar_ap_doc ON ar_ap_entry(doc_id)` 要求每单一条，期初没有单据，需要区分来源：

```sql
-- v20：应收应付期初标记
ALTER TABLE ar_ap_entry ADD COLUMN source TEXT NOT NULL DEFAULT 'DOC';  -- DOC / OPENING
DROP INDEX uk_ar_ap_doc;
CREATE UNIQUE INDEX uk_ar_ap_doc ON ar_ap_entry(doc_id) WHERE source = 'DOC';
CREATE INDEX idx_ar_ap_opening ON ar_ap_entry(source, partner_key, direction, status);
```

- 期初行：`doc_id = 0`、`doc_no = 'QC-' + 序号`、`doc_type = 'OPENING'`、`source='OPENING'`、`biz_date` = 导入日期、`due_date` 空、`settled_cents = 0`、`status='OPEN'`。
- 直接参与现有核销，报表（账龄、应收应付余额）无需改 SQL，只多一批来源为 OPENING 的未结项。
- Excel 列：客户/供应商编码、期初金额（元）、账期到期日（可空）。方向由导入类型决定（应收 1 / 应付 -1）。
- 同一往来单位允许多行导入，逐行成条目；后续核销按现有规则分摊。

### 4.3 资金账户期初（无迁移）

- 用 `fund_account.opening_cents`，不新增记录。
- Excel 列：账户编码、期初余额（元）。只更新该字段，不动已有流水。

### 4.4 拒绝条件与清空重建

- 判定「已有业务流水」：满足任一即拒绝——`stock_ledger` 存在非期初来源的行；存在 `status='APPROVED'` 且 `doc_type` 不是期初导入生成的单据；`settlement` 非空；资金账户存在收付款流水。
- 错误信息必须带依据，例如：「已有库存流水 12 条，期初只能在建账前导入；如需重来请先清空期初」。
- 清空重建（单独操作，需二次确认并自动备份）：
  1. 删除 `source='OPENING'` 的 `ar_ap_entry` 及其核销分摊；
  2. 反审核并删除 `biz_category='OPENING'` 的 `OTH_IN` 单据，回滚流水与结存；
  3. 资金账户 `opening_cents` 归零；
  4. 以上任何一步发现期初之外的数据，中止并提示。
- 清空后重新导入，不提供「覆盖」或「追加」语义。

## 5. 与现有主数据导入导出的关系

- 商品导入新增列：分类路径、条码（多码用 `|` 分隔，第一个为主码）、税率%。
- 供应商/客户导入新增列：税号；客户另加信用额度（元）。
- 仍遵守既有口径：按编码 upsert、空单元格保持原值、表头文字对列、先全量校验、单事务、5000 行 / 5MB 上限。
- 分类路径不存在时不自动建树，整批报错（与「不猜」一致）。

## 6. 对现有报表、页面、打印的影响

| 模块 | 影响 |
| --- | --- |
| 商品列表/表单 | 新增分类树筛选、条码、税率；停用分类视觉标注 |
| 单据录入 | 销售类单据表头新增「业务员」下拉；其他出入库已有业务类型，不变 |
| 单据列表/详情/打印 | 销售类单据增加业务员；往来单位增加税号（打印抬头可选） |
| 库存/销售报表 | 分类筛选按子树；后续业务员维度报表依赖本期字段 |
| 应收应付 | 期初条目进入账龄与余额，核销可用；总余额口径不变 |
| 导入导出 | 列增加，老模板缺列按空值处理；导出列头追加 |

## 9. 仍需拍板的点

1. **税率在单据行的覆盖形式**（推荐 A）：
   - A `doc_line.tax_rate_bp INTEGER` 可空：`NULL` = 继承商品默认，非空 = 本行覆盖。好处是「继承」与「显式 0」可区分；
   - B 非空 + `-1` 表示继承：字段简单，但脏值风险高；
   - C 不允许行覆盖：实现最省，但促销、专票场景无法处理。
2. **单价是否含税的表达**（推荐 A）：
   - A `doc_line.price_includes_tax INTEGER NOT NULL DEFAULT 0` 行级标记，税额与不含税金额分别计算，报表无需猜；
   - B 全局配置一个默认值，行级不可改：实现简单，但同一张单无法混合；
   - C 不做含税价，只存不含税：与现有单据金额最兼容，但录入口径要用户自己换算。
   - **当前状态：未实施**（见 1.3），上述三种方案均未落库。
3. **商品未分类的处理**（推荐 A）：
   - A `category_id = 0`，报表归入「未分类」，不建占位节点；
   - B 迁移时自动建「未分类」节点并把存量商品挂上去，分类树多一个固定节点；
   - C 强制必选：商品新增/导入必须选分类，存量商品下一次编辑时补。
4. **同级重名**（推荐 A）：
   - A 不允许：`UNIQUE(parent_id, name)`，报表与导出不会出现无法区分的同名节点；
   - B 允许：建树更自由，但选分类时必须显示路径，误选风险高。
5. **条码形态**（推荐 A）：
   - A 一商品多码 + 条码全局唯一（`item_barcode`），支持箱码/备用码；
   - B 严格一对一（`item.barcode` 唯一），实现最小；
   - C 多码且条码不唯一：扫码需二次选择，不建议。
   - **当前状态：未实施多码**，实际为一商品一码（见 1.2）；v21 只把预留表的 `item_id` 唯一索引改为普通索引。
6. **职员档案与 `app_user` 的关系**（推荐 A）：

# 成本调整单：设计（待确认）

> 状态：**方案稿，未改任何代码**。确认后按第 9 节实施。
> 版本位置：数量精度 v11、收付款升格 v12，本方案为 **v13**，纯增量，不删不改历史单据与金额。
> 原则：成本重算页保持只读核对，不静默写回；差异只能通过业务单据修正，金额差异用成本调整单，数量差异用盘点单。

## 1. 单据定义

| 项 | 取值 |
| --- | --- |
| `doc_type` | `CST_ADJ` |
| 单号前缀 | `CBTZ`（成本调整），格式 `CBTZ20261112-0001` |
| `stock_mode` | 新增 `StockMode::CostAdjust` |
| `affects_stock` | `true`（写库存流水、改结存金额，但数量变化为 0） |
| `finance_direction` | `0`（不生成应收应付） |
| `partner_kind` | `None`（不绑定往来单位） |
| `role` | `Transaction` |
| `price_source` | `Manual`（单价列不用，金额由录入的调整额决定） |
| 仓库 | 必填（表头一个仓库，明细可逐行带仓库则更灵活；见第 10 节确认项） |

明细字段：

| 字段 | 说明 |
| --- | --- |
| `item_id` | 商品，必填 |
| 仓库 | 跟随表头；如确认逐行指定，则加 `doc_line.warehouse_id`（见确认项） |
| `adjust_cents` | 调整金额（分），带符号，非 0；正数调增结存金额，负数调减 |
| `adjust_reason` | 调整原因，必填（长度 ≤ 100） |
| `qty` | 固定为 0（不参与录入） |
| `price_cents` / `amount_cents` | 固定为 0 / 0，不参与金额计算 |

不关联核对批次：成本重算本身是只读重放，没有可持久化的「批次」概念；把批次号写进单据只会制造一个无法追溯的外键。需要追溯时，靠单据日期、备注「成本重算差异」和审计日志即可。

## 2. 记账语义

审核时逐行：

```text
write_move(biz_type = "CST_ADJ", delta_qty = 0, delta_amount = line.adjust_cents)
```

- `stock_ledger` 新增一条 `qty = 0、amount_cents = ±X` 的流水；`stock_balance.qty` 不变，`stock_balance.amount_cents` 加 `±X`。
- 单位成本没有缓存列，始终由 `amount_cents / qty` 现算，调整后自然生效。
- 不做「调整后再按新单价重算历史出库成本」：历史出库成本是已发生事实，调整只影响之后出库的移动平均单价，这与成本重算的只读定位一致。

边界规则（审核前校验，违反则整单回滚）：

| 场景 | 规则 |
| --- | --- |
| 调整后 `stock_balance.amount_cents < 0` | 拒绝：「调整后结存金额不能为负（当前 X 分）」 |
| 结存数量为 0 且调整后金额非 0 | 拒绝：「零库存不能有结存金额」；数量为 0 时只允许把金额调回 0 |
| 商品/仓库没有结存记录 | 视为数量 0、金额 0，按上一条拒绝 |
| 单行调整额为 0 | 拒绝；整单没有非 0 行也拒绝 |
| 调整额超过 ±9,000,000,000,000 分 | 拒绝（int64 溢出保护） |

`stock_ledger` 现有 `CHECK (qty <> 0)` 会挡住「数量 0、金额非 0」的流水，v13 必须把它放宽为 `CHECK (qty <> 0 OR amount_cents <> 0)`（见第 6 节）。

## 3. 审核与反审核

- 审核：标准单据流程（`DRAFT → APPROVED`），在同一事务内追加流水、更新结存、写审计日志。
- 反审核：沿用通用反向逻辑——为该单据的每条流水追加一条 `qty = -0 = 0、amount = -X` 的 `REVERSE` 流水，结存金额加回 `-X`。**不修改原流水、不重算历史**。
- 反审核的前置校验：若 `当前结存金额 + (-X) < 0`，拒绝并提示「调整单审核后已发生出库，反审核会使结存金额为负；请用新的成本调整单处理」。这是因为该笔调整可能已经被后续出库成本结转消耗，回退无意义且会破坏「结存金额 ≥ 0」的不变量。
- 反审核之后又有新的出入库：不影响，反向流水只是按时间顺序追加；成本重算按流水 id 重放，结果与账面一致。
- 一张调整单只能反审核一次（`VOIDED` 状态保护，沿用现有逻辑）。

## 4. 与报表的关系

| 报表 | 调整行是否显示 | 说明 |
| --- | --- | --- |
| 库存余额表 | 不显示行，但金额已包含 | 直接读 `stock_balance`，无需改 SQL |
| 收发明细 | **不显示** | 该报表按数量汇总收发；调整行数量为 0，显式排除 `biz_type = 'CST_ADJ'` 更清晰 |
| 库存流水 | **显示** | 业务类型显示「成本调整」，数量列 0，金额列带符号；`REVERSE` 行显示「反审核冲销」 |
| 销售毛利 | 历史不变 | 调整不重算已出库成本；只影响之后出库的移动平均单价 |
| 成本重算 | 差异会变少 | 重放时数量 0 的流水直接取存储金额，金额差异被单据修正后账面与重放一致 |

## 5. 权限

- 查看差异：沿用 `stock.read`，不改。
- 生成调整单草稿：沿用 `document.write`（操作员可以准备）。
- 审核/反审核调整单：新增 **`cost.adjust`**（不加种子行，只有 admin 的 `*` 通配覆盖，即仅管理员）。

理由：调整单直接改存货金额与毛利，属于「谁能改账」的职责，不适合和普通出入库共用 `document.write`；但也不必再拆一个 `cost.read`——差异查看是库存报表的一部分。

实现方式：给 `DocumentDefinition` 加 `write_permission` 字段（默认 `"document.write"`，`CST_ADJ` 设为 `"cost.adjust"`），`document_routes` 在审核/反审核（以及「保存并审核」）时按单据类型取权限码；起草、改草稿与删除草稿仍走 `document.write`。

**是否两步**：建议是。起草（`document.write`）与审核（`cost.adjust`）分开，等于「操作员提申请、管理员批」，不需要额外的审批流。

## 6. 迁移 SQL（v13 全文）

```sql
-- v13：成本调整单。
-- 需要重建 doc_line 与 stock_ledger：
--   doc_line 原 CHECK (qty > 0) 挡住数量 0 的调整行，且要新增 adjust_cents / adjust_reason；
--   stock_ledger 原 CHECK (qty <> 0) 挡住「数量 0、金额非 0」的成本调整流水。
-- 其余表不动；历史数据逐列复制，不重算金额。

ALTER TABLE doc_line RENAME TO doc_line_v12;
CREATE TABLE doc_line (
  id                   INTEGER PRIMARY KEY,
  doc_id               INTEGER NOT NULL REFERENCES doc_header(id),
  line_no              INTEGER NOT NULL,
  item_id              INTEGER NOT NULL REFERENCES item(id),
  qty                  INTEGER NOT NULL,
  price_cents          INTEGER NOT NULL,
  amount_cents         INTEGER NOT NULL,
  source_order_line_id INTEGER NOT NULL DEFAULT 0,
  adjust_cents         INTEGER NOT NULL DEFAULT 0,
  adjust_reason        TEXT    NOT NULL DEFAULT '',
  CHECK (qty >= 0),
  CHECK (price_cents >= 0),
  CHECK (amount_cents >= 0),
  CHECK (adjust_cents <> 0 OR qty > 0)
);
INSERT INTO doc_line (id, doc_id, line_no, item_id, qty, price_cents, amount_cents,
                      source_order_line_id, adjust_cents, adjust_reason)
SELECT id, doc_id, line_no, item_id, qty, price_cents, amount_cents,
       source_order_line_id, 0, ''
FROM doc_line_v12;
DROP TABLE doc_line_v12;
CREATE UNIQUE INDEX uk_doc_line_no ON doc_line(doc_id, line_no);
CREATE INDEX idx_doc_line_item ON doc_line(item_id);
CREATE INDEX idx_doc_line_source_order ON doc_line(source_order_line_id);

ALTER TABLE stock_ledger RENAME TO stock_ledger_v12;
CREATE TABLE stock_ledger (
  id           INTEGER PRIMARY KEY,
  doc_id       INTEGER NOT NULL,
  doc_line_id  INTEGER NOT NULL,
  biz_type     TEXT    NOT NULL,
  biz_time     TEXT    NOT NULL,
  warehouse_id INTEGER NOT NULL REFERENCES warehouse(id),
  item_id      INTEGER NOT NULL REFERENCES item(id),
  qty          INTEGER NOT NULL,
  amount_cents INTEGER NOT NULL,
  created_at   TEXT    NOT NULL,
  CHECK (qty <> 0 OR amount_cents <> 0)
);
INSERT INTO stock_ledger (id, doc_id, doc_line_id, biz_type, biz_time, warehouse_id,
                          item_id, qty, amount_cents, created_at)
SELECT id, doc_id, doc_line_id, biz_type, biz_time, warehouse_id,
       item_id, qty, amount_cents, created_at
FROM stock_ledger_v12;
DROP TABLE stock_ledger_v12;
CREATE INDEX idx_stock_ledger_item_wh_time ON stock_ledger(item_id, warehouse_id, biz_time, id);
CREATE INDEX idx_stock_ledger_doc ON stock_ledger(doc_id);
CREATE UNIQUE INDEX uk_stock_ledger_doc_line ON stock_ledger(doc_line_id, biz_type);

-- 权限：cost.adjust 只由 admin 的 '*' 覆盖，不插入 app_role_permission 种子行。
```

说明：

- 重建的是**引用方**表（都引用 `doc_header` / `warehouse` / `item`），没有其他表通过外键引用它们，`foreign_keys = ON` 下重命名不会再被第三方引用改写，安全。
- 重建后索引必须等旧表 `DROP` 之后再建，否则同名索引冲突。
- `adjust_cents <> 0 OR qty > 0` 同时约束：普通行必须有数量，调整行必须有金额（调整行 qty 固定 0）。
- `stock_balance` 无数量/金额 CHECK，不受影响；`doc_header.total_amount_cents` 无 CHECK，调整单可以是负数合计。
- 迁移顺序依赖：v11 已把数量放大 10000，本迁移只做逐列复制，不再次换算。
- checksum / `user_version` / 迁移前自动备份沿用现有机制（v12 → v13 触发备份）。

## 7. 与成本重算页的衔接

- 差异清单每行增加一个操作：
  - `qty_diff == 0、amount_diff != 0`：显示「生成调整单」按钮，点击后把该行（商品、仓库、调整金额 = `amount_diff_cents`、原因 =「成本重算差异」）加入待生成列表，可多选；
  - `qty_diff != 0`：不提供调整入口，提示「数量差异请用盘点单修正」，并给出盘点入口。
- 生成的是**草稿**（`POST /api/cost-adjustments/drafts`），只带差异金额，不自动审核；页面跳转到调整单详情，可改原因、删行、再审核。
- 金额差异的方向：`amount_diff_cents = replay - book`，即「账面应调的增量」，直接作为 `adjust_cents`。
- 生成前重新跑一次重算，避免用过期差异（按钮点击时前端重新请求该行差异，后端按商品 + 仓库现场核对后再写草稿；不一致返回 409 提示刷新）。
- 也支持纯手工新建：成本调整单页面与其它单据一致（草稿、审核、反审核、打印）。

## 1. 已确认的决策

| # | 决策 | 说明 |
| --- | --- | --- |
| C1 | 两个版本共用一套代码、表结构与迁移 | 社区版不是独立分支，数据库文件可直接互换 |
| C2 | 版本差异只按「功能子集 + 规模额度」落地 | 不按单个按钮拆碎，不做时间限制 |
| C3 | 不使用试用期倒计时、运行时长、水印、导出降级、周期联网校验 | 本地环境无可靠时钟与在线状态，且损害正常使用 |
| C4 | 导出不锁死 | Excel、PDF、备份文件的格式与完整性两版一致 |
| C5 | 存量超限数据只读可用 | 拒绝新增与启用，不删除、不截断，可查询与导出 |
| C6 | 能力表单一来源，服务层统一判定 | 路由与界面不出现版本字符串判断 |

## 2. 两个版本的定义

「版本」指能力层级，与部署形态（单机版 / 网络版）是两个维度。首版把网络部署作为全功能版能力，社区版只提供单机版；这是产品分层选择，不是技术限制。

| 项 | 免费社区版 | 全功能版 |
| --- | --- | --- |
| 定位 | 可长期使用的免费版本，覆盖小规模进销存闭环 | 面向规模更大或有协作需求的用户，开放完整能力 |
| 目标用户 | 个体户、小门店、单人操作、试用与评估 | 多岗位协作、主数据与单据量更大的商贸/轻工企业 |
| 功能范围 | 能力表的子集，见第 4 节 | 能力表全集 |
| 规模上限 | 见第 5 节 | 商品、单据、仓库、往来单位、职员不设上限；账号上限见第 5 节 |
| 部署形态 | 仅单机版 | 单机版与网络版（`--server`） |
| 用户与协作 | 1 个账号，不启用 RBAC | 最多 30 个账号，启用 RBAC 与数据权限 |
| 数据 | 与全功能版同构，可直接互换 | 同左 |
| 版本切换 | 首版为独立安装包；替换程序即可，不迁移数据 | — |

两版都不是「另一套产品」：同一份代码、同一套表结构、同一套迁移。社区版少的只是入口与额度，不是数据能力。

## 3. 差异清单的结构

版本差异只按两类落地，另列一类「明确不作差异」的项，防止后续把版本差异扩大成任意功能开关。

**A. 功能子集**

| 判定 | 含义 | 产品表现 |
| --- | --- | --- |
| `full` | 社区版完整可用 | 入口可见，功能与全功能版一致 |
| `limited` | 社区版可用但受规模上限 | 入口可见，超过上限时拒绝新增并提示 |
| `hidden` | 社区版不开放 | 入口不可见，直接调用 API 被拒绝 |

功能子集以「整块能力」为单位，不按单个按钮拆碎；同一功能内的操作（新增、修改、审核、反审核）作为一组，不单独设限。

**B. 规模额度**

- 只对「会持续增长、且与使用规模相关」的实体设上限：商品、业务单据、仓库、往来单位、职员、用户账号。
- 额度按当前存在的记录数判定，不按自然月/自然年重置；修改、查询、导出不消耗额度，只有新增与启用时校验。
- 每项额度在能力表中对应一个 `limit_key`；数值由本文维护，代码不内置数字。

**C. 明确不作差异的项**

| 项 | 约束 |
| --- | --- |
| 数据表结构与迁移 | 两版完全一致，共用 schema 版本号 |
| 计算规则 | 金额/数量精度、成本口径、库存与往来规则一致 |
| 导出 | Excel、PDF、备份文件的完整性与格式一致，不锁死、不加水印 |
| 数据归属 | 数据保存在用户自己的目录或服务器，不因版本被锁定或上传 |
| 安全基线 | 口令哈希、会话、CSRF、审计日志不因社区版降级 |
| 历史数据查询 | 本地数据可全部查询，不用「只给 N 个月」制造差异 |

每条差异最终都必须落到能力表的一行（功能 id + 社区版可用性 + 上限键），不能只存在于宣传页或口头约定。

## 5. 首版额度

| 项目 | 社区版 | 全功能版 | 参照依据 |
| --- | --- | --- | --- |
| 商品数量 | 500 个（不含停用） | 不限 | 智慧记免费版 500 个；生意专家免费版 99 个；秦丝免费版总商品数不限 |
| 业务单据总量 | 5,000 张（采购、销售、库存、收付款合计；不含草稿与已作废） | 不限 | 智慧记、秦丝免费版均为 100 单/月；按 4 年折算约 4,800 单，取整 5,000，并改为总量以避免按月重置 |
| 用户账号 | 1 个 | 30 个 | 智慧记、柠檬云免费版均为 1 人；全功能版按技术方案的 10–30 并发目标取上限 30 |
| 仓库数量 | 3 个 | 不限 | 秦丝免费版最多 3 个（专业版 70 个） |
| 门店数量 | 1 个 | 1 个 | 智慧记免费版 1 个店铺；当前产品不区分门店，两版一致 |
| 往来单位 | 500 个（客户 + 供应商合计） | 不限 | 与商品同量级；秦丝上限 15 万不具参考性，智慧记未公开 |
| 职员档案 | 10 人（非登录账号） | 不限 | 无公开对标；按单店小团队规模设定，登录账号另受 1 人限制 |
| 报表 | 5 张基础报表（库存余额、库存流水、进销存汇总、销售明细、应收应付余额） | 全部报表 + 经营看板 + 自定义报表 | 免费版普遍保留基础报表，高级报表与经营分析分层 |
| 打印模板 | 每种单据 1 套内置模板，不可自定义 | 全部内置模板 + 自定义模板 | 秦丝定制模板单独收费；生意专家免费版不含自定义打印 |
| 数据导出 | 不限 | 不限 | 技术约束：导出不锁死，见技术方案 6.9 |
| 历史数据查询 | 不限 | 不限 | 智慧记免费版仅可查 14 个月；本项目数据在本地，不用时间维度设限 |

这些数值是首版设定，不是技术约束。运营反馈需要调整时，只改本文与能力表数值，技术方案 6.9 的结构不变。

## 7. 非额度待确认项

| 编号 | 事项 | 首版处理 | 需谁确认 |

| N5 | 额度调整的公告与兼容 | 调低上限不删除存量数据；变更写入发布说明 | 产品 + 运营 |

## 8. 维护规则

- 能力表是唯一事实来源：新增或调整功能时，先改 `tools/codegen/schema/editions.json`，再回填本文第 4 节；两处不一致视为文档缺陷。
- 额度数值只在本文第 5 节维护；代码与配置只引用 `limit_key`，不内置数字，避免文档与实现各说一套。
- 调整额度不改变技术方案 6.9 的结构；只有新增限制类型（例如增加「并发数」）才需要改技术方案。
- 发布前检查：
  1. 社区版构建中 `hidden` 功能无入口，API 返回统一错误码；
  2. `limited` 功能达到上限时返回明确文案，存量数据仍可查询与导出；
  3. 同一数据库文件在两版之间切换打开，表结构、迁移版本与导出结果一致。
- 变更记录写入提交信息与发布说明，本文不维护逐次修改日志。

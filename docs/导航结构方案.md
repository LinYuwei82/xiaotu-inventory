## 2. 分组设计

### 2.1 两种切法

| 切法 | 结构 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 按业务流程（推荐） | 采购、销售、库存、财务、报表、基础资料、系统 | 和日常动作一致，录单的人在自己那一组里就能完成 | 单据与档案同处一屏，配置类页面要靠组顺序区分 |
| 按数据对象 | 单据、主数据、账务、报表、系统 | 概念干净，新增页面时归属一目了然 | 「单据」一组会堆 10 项，等于把现在的问题换个名字 |

推荐前者：现在的痛点是一屏 23 项太长，按流程切能把「录单」相关的动作聚到一起。主数据统一放「基础资料」（商品、单位、仓库、客户、供应商），采购/销售组只保留单据动作，档案入口不再散落在业务组里。

### 2.2 推荐结构（7 组，23 项）

| 组 | 组内条目 | 归组理由 |
| --- | --- | --- |
| **采购** | 采购入库、采购退货 | 只保留采购动作，供应商档案统一到基础资料 |
| **销售** | 销售出库、销售退货、销售订单 | 订单与出库同一业务链；客户档案统一到基础资料 |
| **库存** | 库存（余额/流水/成本重算）、调拨、盘点、其他入库、其他出库 | 都会直接改库存，是仓管每天用的入口 |
| **财务** | 收付款、对账单、成本调整、资金账户 | 收付款依赖账户；成本调整改结存金额与毛利，归财务更符合「谁能改账」 |
| **报表** | 报表 | 作为一级项直接入口，不建组；配置里保留空的 `group` 字段，将来拆页时只改数据，不引入「单条目组自动降级」规则 |
| **基础资料** | 商品、计量单位、仓库、客户、供应商 | 全部公共档案集中管理，不专属某个业务组；仓库不并进库存组，避免和「库存」页面混淆 |
| **系统** | 用户、审计日志、打印模板 | 管理配置类，频率低，放最后 |

和你给的示例相比，只有一处调整，理由如上：

1. **资金账户放财务，不放系统**：它不是系统配置，而是开收付款单时必须选的档案；放系统会让财务人员多跳一层。

客户与供应商已确认集中到「基础资料」，采购/销售组只保留单据入口，导航里不再出现「采购里找供应商、销售里找客户」的分散入口。

如果同意，组顺序按「采购 → 销售 → 库存 → 财务 → 报表 → 基础资料 → 系统」。单据量少的用户会更常落在前四组，基础资料与系统属于配置期才用。

## 4. 技术实现

### 4.1 现状

- 单页应用，无框架、无路由库；页面切换是 `mountPage()` 直接替换 `<main>` 内容。
- hash 只承载单机版一次性 token（`#t=...`），不承载页面。
- 导航数据 = `pages.json` + `FIXED_PAGES`，渲染成一组平铺 `<button>`；点击时在 `all` 里按 key 找页面。
- 权限判断在 `can(permission)`，数据来自 `/api/me` 的 `permissions`。

### 4.2 改动面

| 文件 | 改什么 |
| --- | --- |
| `web/app.js` | 新增 `NAV_GROUPS` 常量（组 key、标题、顺序）；`FIXED_PAGES` 每项加 `group`；生成页从 `pages.json` 读 `group`；导航渲染改为「组头 + 子项」；`mountPage` 的高亮改为同时标记组头；点击处理先判组头再找页面；加 hash 路由与 `localStorage` |
| `web/styles.css` | 组头、子项缩进、展开箭头、组激活态、`nav` 滚动；不引入图标 |
| `tools/codegen/generate.py` | 往 `pages.json` 每项补 `permission`（`permissions.read`）与 `group`（来自 schema 的 `nav_group`），并校验组名在允许集合内 |
| `tools/codegen/schema/masterdata.json` | 每张表加 `"nav_group"`：`item/unit/warehouse/customer/supplier → master`、`fund_account → finance` |
| `web/gen/pages.json` 等生成物 | 由 `generate.py` 重新产出，不手改 |

**不需要改后端**：导航只是展示层；接口的 `guard(...)` 已经是权威判定，导航隐藏不构成安全边界。

### 4.3 权限过滤放在哪一层

- 仍然在**前端导航层**做一次展示过滤：`can(page.permission)` 为假就不渲染该项。
- 生成页补上 `permission` 后，「商品 / 单位 / 仓库 / 客户 / 供应商 / 资金账户」也会按 `item.read` 等权限隐藏，不再出现「菜单能点、进去 403」。
- 组内条目全部被过滤掉时，整组不渲染，避免空组。

### 4.4 新增一个页面时改哪里

| 页面类型 | 改法 |
| --- | --- |
| 生成页（主数据 CRUD） | `masterdata.json` 加表并填 `nav_group` → 跑 `generate.py` → 导航自动出现 |
| 固定页（单据/报表等） | `web/app.js` 的 `FIXED_PAGES` 加一项：`key`、`title`、`group`、`permission`、`render` |
| 新增分组 | 只在 `NAV_GROUPS` 里加一行，并确认组顺序 |

### 4.5 页面路由（最后一笔）

- 形式：`#/<key>`，key 沿用导航的固定英文短名，例如 `#/purchase`、`#/sales-orders`、`#/reports`。
- 优先级：hash > `localStorage` 上次页面 > 默认页（第一个可访问页）。
- 未知 key 或无权页面：用 `history.replaceState` 回默认页，不留在历史里。
- 菜单点击：`location.hash = "#/<key>"`，每个页面一条历史；重复点当前页不动作。
- 首次进入与兜底用 `replaceState`；浏览器前进 / 后退由 `hashchange` 直接挂载，不再写历史。
- 单机版边界：`shell/mac/webview.mm` 保持不开 `allowsBackForwardNavigationGestures`，也不加后退 / 前进菜单。刷新保页在单机版有效；前进 / 后退只在 `--server` 浏览器里有效。原因是侧栏已经是完整导航路径、录入页脏标记会拦住误跳、横扫手势还会和明细表的横向滚动冲突。

离开确认用页内自绘的确认层，不调用 `window.confirm`：WKWebView 没有实现 `WKUIDelegate` 的确认面板，原生 `confirm()` 会静默返回 `false`。关闭窗口的 `beforeunload` 同样只对 `--server` 的浏览器有效，单机版关窗不会拦截。

## 5. 迁移与风险

| 项 | 影响 | 处理 |
| --- | --- | --- |
| 旧链接 / 书签 | 现在没有页面级 URL，书签只能落在「商品」，不会失效 | 新增 `#/<key>` 后，旧书签照旧打开默认页；`#t=` 仍优先处理，处理完再进路由 |
| 单机版一次性 token | 若先解析路由可能吞掉 `t` 参数 | 保持现有顺序：先匹配 `#t=`，换会话并 `replaceState`，再按路由或默认页挂载 |
| 打印视图 | 打印是服务端渲染的独立页面，侧栏不参与；`@media print` 已隐藏 `.sidebar` | 无影响 |
| CSV / XLSX 导出 | 走接口下载，与导航无关 | 无影响 |
| WKWebView 兼容 | 只用到 `localStorage`、`hashchange`、普通 DOM；macOS 13+ 均支持 | 不用 `<details>`（各版本样式差异大），用 button + div 自己控制展开 |
| 权限回归 | 隐藏逻辑从「2 项」扩大到「所有带 read 权限的页」 | 冒烟时用 operator / viewer 各点一遍，确认组不空、页面可达 |
| 导航状态与页面不一致 | 直接改 hash 进入某页时组可能未展开 | 进入页面时强制展开其所在组 |

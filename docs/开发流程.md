# 双机开发流程

项目在两种机器上并行推进：家里性能好、可长时间运行；公司时间碎片化。本文约定分工、边界、分支与同步纪律，避免两台机器互相覆盖。构建方式、preset 名称见 [README](../README.md) 第 2 节，夜间任务见 [tools/nightly](../tools/nightly/README.md)。

## 1. 分工

| 机器 | 代号（分支前缀） | 负责范围 | 特点 |
| --- | --- | --- | --- |
| 家里（Mac mini） | `macmini` | `core/`、`server/`、`web/`、`tests/`、`docs/`，以及迁移与业务逻辑 | 性能好、可 24 小时运行，承担夜间任务 |
| 办公室（Windows） | `macbook` | `shell/win/`、`packaging/win/` 与 Windows 侧的打包验证 | 时间碎片化，改动集中在壳与安装包 |

- 跨范围的改动（例如新增一张表的完整链路）由 Mac 侧完成 `core/server/tests/gen`，Windows 侧只做壳的加载与打包，不碰业务实现。
- 需要在另一台的范围内改东西时，先在群里说明，避免同一文件两端同时改。

## 2. 目录边界

| 目录 / 文件 | 谁能改 | 说明 |
| --- | --- | --- |
| `core/`、`server/` | 仅 Mac mini（`macmini`） | 业务内核、HTTP 层、迁移脚本 |
| `web/`、`tests/` | 仅 Mac mini | 页面、样式、前端交互、冒烟与单测 |
| `tools/codegen/` | Mac mini 独占 | schema、模板、生成器只在 Mac 侧改 |
| `core/**/gen/`、`server/**/gen/`、`web/gen/` | Mac 侧生成并提交 | Windows 侧 `pull` 后直接使用，**不要手改生成物** |
| `docs/` | Mac mini | 方案文档、接口约定、流程说明 |
| `shell/win/`、`packaging/win/` | 仅 Windows（`macbook`） | Windows 壳与安装包 |
| 根 `CMakeLists.txt` 中引入 `shell/win` 子目录的几行 | 仅 Windows | 其余构建逻辑仍归 Mac 侧 |
| `CMakePresets.json` | Windows 默认维护，Mac 侧改动需先说明 | 属于共享文件，见下节 |

### 2.1 共享文件

以下四个文件同一时间只由一方修改，另一方需要动时先在群里提出，改完对方再拉：

- 根 `CMakeLists.txt`（新增子目录、改构建目标等）
- `CMakePresets.json`
- `shell/CMakeLists.txt`
- `README.md`

共享文件的改动不夹带在功能提交里，单独一笔提交，提交信息写清动机，方便对方判断是否需要立即同步。

### 2.2 本阶段边界

Mac 侧正在推进 schema v11（数量小数）、v12（收付款与资金账户）、v13（成本调整单）。这段时间 Windows 侧只做壳与打包：不修改业务逻辑、不改 schema，壳只负责加载前端；测试时用哪一版数据库都可以，以能启动、能打开页面为准。

生成物边界：所有 `gen/` 与 `cmake/generated_sources.cmake` 由生成器产出，首行带 `AUTO-GENERATED` 标记。公司那台如果发现生成物有问题，改的是「描述问题的文档或 issue」，不是 `gen/` 里的文件；由家里改 schema / 模板后重新生成。

## 3. 分支规则

- 分支名 = 机器前缀 + `/` + 短任务标记，例如：
  - `macmini/商品表单`
  - `macbook/win-shell`
- 每次从最新 `main` 新建，不长期挂着旧分支；Windows 侧的壳与打包分支固定用 `macbook/win-shell`。

```bash
git switch main
git pull --rebase origin main
git switch -c macbook/win-shell
```

- 动手前先 `git pull --rebase`，小步提交；Windows 侧的提交只在 Windows 那台机器上产生，不在 Mac 上代为提交。
- 已经推送的提交不再 rebase。需要跟进 `main` 时用合并提交，或另起新分支，避免改写远端历史：

```bash
git fetch origin
git merge origin/main
```

- 合并完成后删除本地与远端分支，另一台执行 `git fetch --prune` 清掉过期引用：

```bash
git push origin --delete macbook/win-shell
git branch -d macbook/win-shell
# 另一台
git fetch --prune
```

- `main` 保持可构建；不直接在 `main` 上做未完成的改动。

## 4. 合并门槛

合并到 `main` 前，两边都要构建通过，构建不过的分支留在各自分支上，不合并：

1. **ctest 全绿**：

   ```bash
   ctest --test-dir build/release --output-on-failure
   ```

   改了 `core/`、`server/`、`tools/codegen/` 时，先按 README 重新配置并全量构建，再跑测试。

2. **手动点一遍改动的路径**：启动对应形态（单机版或 `--server`），把本次改动涉及的页面/接口实际走一遍；涉及单据的，至少走「新建 → 审核 → 反审核」。

3. **Windows 壳能构建并启动**：`shell/win/` 或 `packaging/win/` 有改动时，在 Windows 上完成构建与实际启动，确认能加载前端页面。

只改文档或样式的分支也要跑一次构建，确认没有连带破坏。

## 5. 每日同步纪律

- **开工先 pull**：`git switch main && git pull --rebase origin main`。
- **收工前 commit + push**：当天的工作即使没完成也要落到远端，不留只存在于本机工作区的改动。
- **做到一半用 wip 分支**：未完成、不能进 `main` 的改动推到 `wip/<机器>-<日期>`，例如：

  ```bash
  git switch -c wip/macmini-20261112
  git add -A && git commit -m "wip: 库存流水查询（未完成）"
  git push -u origin wip/macmini-20261112
  ```

  第二天从该分支继续，完成后按第 3 节流程合并、删除；未推送的提交可以 rebase，已推送的用合并提交跟进。
- 不在工作区留跨天的未提交改动；不在两台机器上同时改同一文件。

## 6. 接口契约

- `docs/` 下的接口约定（路由、字段、错误码、权限码）由公司那台维护。
- 契约改动当天推到远端，家里那台以远端文档为准实现，避免「口头约定」导致的字段漂移。
- 契约与实现冲突时，先改文档再改代码；生成器的 schema 变更仍由家里执行。

## 7. 环境一致性

- 两台机器都使用 `CMakePresets.json` 里的 `macos-dev` / `macos-release`，不各自发明构建参数。
- 依赖版本：`vcpkg.json` 声明依赖，未安装 vcpkg 时回落到 `third_party/` 内嵌头文件。
- **不同步**：`build/`、`~/.ccache`（或 `.ccache/`）、`.vcpkg-cache/`、`tools/codegen/.venv/`。这些是机器本地缓存，两台各自编译，避免架构/路径不一致导致的怪问题。
- vcpkg 的 `builtin-baseline` 用于锁定依赖版本；**当前仓库尚未写入 baseline**。在补上之前，以 `third_party/` 内嵌头为准，两台不要一方启用 vcpkg、另一方用内嵌版本做对比测试。补齐 baseline 属于构建体系变更，按第 2 节由家里执行并通知另一台。

## 8. 夜间任务（仅家里）

- 入口：`tools/nightly/nightly.sh`，launchd 模板：`tools/nightly/com.simem.xiaotu.nightly.plist`，安装步骤见 `tools/nightly/README.md`。
- 内容：全量构建 → ctest → ASan/UBSan 构建与测试（独立 `build/asan`）→ clang-tidy（缺失时 cppcheck）扫描 → 日志按日期落盘。
- 失败通知通过 `XIAOTU_NIGHTLY_WEBHOOK` 配置；未配置时只写日志，不打扰。
- 脚本只提供模板，**不在仓库里自动加载 launchd**；是否启用由家里那台手动决定。

## 9. 常用命令速查

```bash
# 开工
git switch main && git pull --rebase origin main

# 新建任务分支
git switch -c macbook/win-shell

# 构建 + 测试（发布态）
cmake --preset macos-release && cmake --build --preset release
ctest --test-dir build/release --output-on-failure

# 开发态（改前端）
cmake --preset macos-dev && cmake --build --preset dev

# 收工
git add -A && git commit -m "feat: …" && git push -u origin HEAD

# 合并前（已推送的提交不改写历史）
git fetch origin && git merge origin/main

# 清理已合并分支
git push origin --delete <分支名> && git branch -d <分支名> && git fetch --prune
```

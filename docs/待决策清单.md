# 待决策清单

本文件只记录需要产品口径拍板、尚未改动代码的问题。每条给出当前实现、影响与可选方案，未做任何修改。

## 1. 收发明细与进销存汇总对 `qty = 0` 金额的口径不一致

**当前实现**

- 收发明细（`/api/reports/goods-flow`）只输出期初数量、收入数量 / 金额、发出数量 / 金额，期初不含金额；金额只累计 `qty > 0` 与 `qty < 0` 的流水。
- 进销存汇总（`/api/reports/inventory-summary`）的期初金额对期间之前的全部流水求和，入库 / 出库金额同样按 `qty > 0` / `qty < 0` 归类，`qty = 0` 但金额不为 0 的流水（如只调整金额的成本调整）会落到期初金额或两边都不计。

**影响**

同一期间、同一商品，两张报表的期初 / 期末金额可能对不上，差额来自 `qty = 0` 的金额行。

**可选方案**

- A：两张报表都只按数量方向归类，`qty = 0` 的金额单列「其他调整」列。
- B：两张报表都把 `qty = 0` 的金额计入期末金额所在侧，并在口径说明里写明。
- C：保持现状，但在报表页脚注明两者差异来源。

## 2. 反审核回冲流水按反审核当天记账

**当前实现**

反审核给原单据追加一条反向流水，`biz_time` 取反审核操作当天，而不是原单据日期。

**影响**

按单据日期查询历史期间时，该期间的收入 / 发出数量不会因事后反审核而减少；反审核的影响落在操作当天所属期间。跨月反审核会让两个期间的报表都出现「回冲」，与「按单据日期归属」的直觉不一致。

**可选方案**

- A：回冲流水沿用原单据的业务时间，历史期间报表随之变化（需要明确「重算历史期间」的提示）。
- B：保持按操作日记账，但在流水与报表中标注「反审核回冲」及其原单据日期。
- C：保持现状，仅补文档说明。

## 3. 撤销收付款不回退历史期间对账单

**当前实现**

撤销收付款会新增一条金额为负的收付款记录，`settled_on` 取撤销当天；历史期间的对账单仍包含原收付款，不会被回退。

**影响**

对账单反映的是「当时发生过什么」，不是「现在回看应该是什么」。核对旧期间时需要结合撤销记录一起看。

**可选方案**

- A：对账单按「当前有效」口径重算，撤销时把原记录从历史期间剔除（需要保留审计痕迹）。
- B：保持「事实发生」口径，在对账单上把撤销行标红并给出净额。
- C：保持现状，仅补文档说明。

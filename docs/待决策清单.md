# 待决策清单

本文件记录需要产品口径拍板的问题。已定条目保留结论、实现位置与影响，未定条目继续列出当前实现与可选方案。

## 1. 已定：`qty = 0` 但金额不为 0 的流水单列「其他调整」

**结论**

数量为 0、只调整金额的流水（如成本调整）在**收发明细**与**进销存汇总**中单列「其他调整（元）」列，**不并入收入 / 发出两侧**。期末金额 = 期初 + 入库 − 出库 + 其他调整；期末数量不受影响。

**实现**

- 收发明细：`GET /api/reports/goods-flow` 增加 `adjust_amount_cents`，页面、CSV、XLSX、打印四处同源。
- 进销存汇总：`GET /api/reports/inventory-summary` 增加 `adjust_amount_cents`，期末金额按上式重算。
- 库存流水仍逐行展示原始流水，不受此口径影响。

## 2. 已定：反审核回冲按操作日入账，但必须标注「反审核回冲」与原单据日期

**结论**

反审核给原单据追加的反向流水沿用**反审核操作当天**作为 `biz_time`（不重算历史期间），但流水与报表必须标注「反审核回冲」并给出原单据日期。

**实现**

- 库存流水（页面、JSON、CSV、XLSX、打印）统一输出 `反审核回冲（原单 YYYY-MM-DD）`；`*_REVERSE` 类型输出 `X回冲（原单 YYYY-MM-DD）`。
- 原始凭证号仍为原单号，`doc_date` 单独返回，便于跨期追溯。

**影响**

历史期间的收入 / 发出数量不会因事后反审核而减少；反审核影响落在操作当天所属期间，核对旧期间时需结合回冲行与原单日期一起看。

## 3. 已定：撤销收付款保持事实发生口径，对账单标注撤销行并给出净额

**结论**

撤销收付款不删除、不回退历史期间的原记录，而是新增一条金额为负的收付款记录，`settled_on` 取**撤销当天**。对账单继续按「当时发生过什么」列示，同时：

- 撤销行标注为「收款撤销 / 付款撤销」，摘要给出被撤销的原单号，并在页面着色提示；
- 对账单汇总给出「其中撤销」金额与笔数，以及「期间核销净额 = 收款/付款 − 撤销回冲」；
- CSV、XLSX、打印与页面同一口径。

**实现**

- `GET /api/reports/statement` 的每行增加 `is_reverse` / `reverses_no`，结果增加 `reverse_cents` / `reverse_count` / `settle_net_cents`。
- 对账单页面、CSV、XLSX、打印均输出撤销标记与净额。

**影响**

核对旧期间时，原收付款仍在原期间，撤销出现在撤销当天所属期间；净额用于快速判断期间真实回款 / 回款冲回情况。

## 4. 已定：单据号规则本版固定，不提供配置

**结论**

单据号固定为「前缀 + 日期 `YYYYMMDD` + 4 位序号」（例如 `XSCK20261113-0001`），前缀按单据类型在 `core/src/doc_number.cpp` 硬编码，序号按业务日期分段。本版**不提供前缀、位数、分隔符的配置**，系统参数页只读展示该口径。

**说明**

这不是待补缺口，也不再列为待决策项；如后续确需自定义编号，按新需求单独立项，涉及历史单号唯一性与并发生成规则。

## 5. 已定：多角色不做

**结论**

不做多角色（用户与多角色的并集）。六个角色够用，兼岗通过调整角色分配解决，不为个别人把两个角色的权限叠在一起。

**理由**

多角色要动权限加载与所有 `*.read` 判断：`app_user` 由单个 `role_id` 改为关联表，登录、会话、每个接口的权限码校验与前端 `can()` 都要改成并集判断，改动面覆盖全部模块，收益不抵成本。

## 6. 已定：Q4 多计量单位不做

**结论**

不做多计量单位。数量按 4 位小数存储已够表达，箱 / 瓶换算走条码或备注；做多单位要动数量口径与全部报表（库存、流水、成本、打印、导出），本版不引入。

## 7. 已定：Q5 批次 / 序列号 / 保质期不做，只留数据缝

**结论**

不做批次 / 序列号 / 保质期。真正需要批次时的最小路径是「**批次号一个文本字段 + 可按批次查询**」；保质期与先进先出（FIFO）不在范围内。

**数据缝**

`doc_line` 与 `stock_ledger` 各预留 `batch_no`、`expiry_date` 两列（`TEXT NOT NULL DEFAULT ''`）。**仅为将来预留**：当前不写入、不显示、不参与任何计算，也不建索引。不引入通用扩展字段表、先进先出钩子或可插拔维度等抽象。

**测试**

只断言两列存在、默认为空串、现有单据与流水写入后仍为空，防止将来误写。

## 8. 已定：Q12 针式纸型与验收标准

**结论**

针式纸型定两档：**241×140** 与 **241×93**，其余尺寸走自定义纸型。验收标准为「**套打偏差 ≤1mm、连续打印 20 张不跑纸**」；真机只负责验证，不再讨论纸型方案。

## 9. 已定：Q16 审计保留 180 天

**结论**

审计日志保留 **180 天**。到期不是删除，而是**打包归档后清出主库**；归档与备份同一节奏（保留 30 份 + 每月 1 份）。

**未定部分**

Q16 的另一半「备份是否加密」仍未拍板，不在本条结论内。

## 10. 已定：Q17 数据权限不做 1.1 白名单

**结论**

不做 1.1 的「用户-仓库白名单」，除非确认真实存在门店 / 业务员之间互相隔离的需求。当前口径维持所有登录用户可见全部仓库数据，可见范围由角色权限控制。

## 11. 已定：Q18 外部对接不做

**结论**

不做外部系统对接。**Excel 导入导出即为对接面**，第三方系统通过导入导出文件交换数据，不提供 API 级集成。

## 12. 已定：Q19 License 与防拷贝不做加密狗

**结论**

不做加密狗，也不做强防拷贝。社区版免费、专业版靠功能差异分层，License 只做弱校验。

## 13. 已定：Q23–Q26 更新策略取最小值

**结论**

- 检查频率：**启动时查一次 + 每日查一次**。
- 通道：**只开 stable**，不做 beta 与灰度。
- 安装方式：**不做强制升级与静默安装**，只在启动时提示。
- Windows：首发**手动下载安装包**，不接入 WinSparkle。

## 14. 已定：Q11 成本口径与计价方法

**结论**

- 计价方法维持**移动加权平均**，不做先进先出，不做个别计价。
- 库存成本口径**默认含税**，保留系统参数里的含税 / 不含税切换开关；切换**只影响此后审核的单据**，历史单据的结存、流水与毛利不重算、不回填。

**理由**

- 目标客户以小规模纳税人为主，进项税不可抵扣，含税成本即真实成本；按不含税记账会低估成本与毛利。
- 先进先出依赖批次，而 Q5（批次 / 序列号 / 保质期）已冻结，单独做 FIFO 没有可靠的成本层依据，不成立。

**实现**

- 参数：`app_setting.cost_basis`（`INCLUSIVE` 默认 / `NET`）与 `cost_basis_changed_at`，见 v33 迁移。
- 单据行保留 `tax_rate_bp`、`price_includes_tax`、`net_cents`、`tax_cents`；库存成本取 `amount_cents`（含税）或 `net_cents`（不含税）。
- 报表与收发明细标注切换日，历史期间不重算。

**影响**

切换口径后，新审核单据的入库成本、出库成本与毛利按新口径计算；切换前后的数据不能直接横向比较，核对时以切换日分段。

# 发行与安装说明

当前版本 1.0.10。分发方式、发版清单与更新链路现状统一放在本文件。
签名状态与 Windows 未签名分发注意事项已拆分到独立文档，见下方「相关文档」。

## 1. 当前分发方式（已定）

- **下载页 + 应用内更新（macOS）**：安装包与清单发布在 `https://dl.xiaotu.online/`（阿里云 OSS 香港，自定义域名直连源站，无 CDN 层），macOS 应用启动 30 秒后自动检查，之后每 24 小时检查一次，发现新版本后由用户确认安装。
- **清单已启用**：`https://dl.xiaotu.online/xiaotu/updates/stable/manifest.json`（v2 统一清单，两平台同一份），`appcast.xml` 在同一目录。每次发版用 `tools/release/publish_macos.sh` 同步；不发版不要手改清单，否则客户端会提示有新版却拿不到包。
- **Windows：自研更新链路已接入**：不接 WinSparkle；`shell/win/updater_win` 负责清单拉取、Ed25519 验签、SHA256 校验与 ISCC 静默安装重启，前端「软件更新」卡片已适配 Windows 桥；清单同为 v2 `manifest.json`。1.0.6 真机验收已过（检查 → 下载 → ISCC 静默安装 → 重启 → 版本核对全链路），正式分发仍以客户从下载页获取安装包为主。
- 分发时同时发出下载页链接、安装包哈希与客户安装说明（见下方相关文档）。

## 2. 首次打开放行方式

macOS 包已用 Developer ID 签名并公证 + staple，正常双击即可打开；Windows 安装包未签名，首次打开会被 SmartScreen 拦一次，点「更多信息 → 仍要运行」即可。

**完整客户指引见 [客户安装说明.md](客户安装说明.md)**；发版者内部的分发 Checklist、签名后续计划与边界说明见 [未签名分发注意事项.md](未签名分发注意事项.md)。

## 3. 手工发包清单

发版前逐条打勾：

- [ ] 工作区干净，`git status` 无未提交改动。
- [ ] `bash tools/ci/check.sh` 完整通过（含 codegen、第三方补丁、前端语法、平台泄漏与 ctest）。
- [ ] `VERSION.txt` 已改为目标版本，`README` 标题与版本说明同步。
- [ ] 打发布 tag：`python3 tools/release/release_tag.py create --push`（生成并推送 `v<semver>+<seq>`，构建号 `build = seq`）。
- [ ] 走 CI 发布（tag 触发 `release-windows.yml`）时，CI 负责 Windows 构建、清单（有 `docs/release-notes-<版本>.html` 时写 `notes_url`）、上传 OSS、线上校验，并创建/更新 GitHub 与 Gitee Release；本机只需完成下面 macOS 两行与最终验收。
- [ ] macOS：带签名、公证与 `XIAOTU_BUILD=<tag 序号>` 跑 `tools/package/package_macos.sh`，得到 `dist/xiaotu-inventory-<版本>.dmg`。
- [ ] macOS：`BUILD=<tag 序号> PRODUCT=xiaotu tools/release/publish_macos.sh`，确认上传、验签与预热全部成功。
- [ ] Windows：`tools\package\package_windows.ps1 -Build <tag 序号>` 一键出包（服务端与壳同一构建号），产物为 `dist\xiaotu-inventory-<版本>-win64-setup.exe` 与 `dist\xiaotu-inventory-<版本>-win64.zip`。
- [ ] Windows：两个产物拷到 Mac 后执行 `BUILD=<tag 序号> tools/release/publish_windows.sh`（或在 Windows 上 `publish_windows.ps1 -Build <tag 序号>`），确认 `xiaotu/updates/stable/manifest.json` 的 `platforms.windows` 已更新且验签通过。
- [ ] 如使用 CI 产物，核对同目录 `SIGNING.txt` 与安装包签名状态一致（本地 `tools\package\package_windows.ps1` 产物未签名，不生成该文件）。
- [ ] 从下载页实际下载一次，挂载后确认 `codesign --verify --deep --strict` 与 `spctl -a -vv` 通过。
- [ ] 用旧版本客户端实跑一次自动更新，确认弹窗、下载、替换与重启。
- [ ] 按 [未签名分发注意事项.md](未签名分发注意事项.md) 的 Checklist 核对 Windows 分发动作；把 [客户安装说明.md](客户安装说明.md) 随包发出。
- [ ] 发版后：把 `dist/manifest.json` 里 `platforms.macos.artifacts.dmg.size` 与 `platforms.windows.artifacts.setup.size` 抄回 [进销存技术方案.md](进销存技术方案.md) 的「包体可控」行（注明版本与核对日期），避免文档数值随发版漂移。
- [ ] 给客户一句话：「装完回我一句能不能正常打开」；收到回复后记录客户、系统版本与结果。

## 4. 更新链路现状

- macOS 单机版已启用并端到端实测：启动 30 秒首查、之后 24h±2h；清单 Ed25519 验签；按 `version` 发现新版本后中文 Sparkle 弹窗确认，下载并原子替换 `/Applications/小兔进销存.app`，重启后版本号更新，`codesign --verify` 与 `spctl -a -vv` 通过。清单检查失败按 1 分钟 / 10 分钟 / 1 小时退避，成功一次即恢复 24h 节奏。
- 发版必须同步清单：`BUILD=<tag 序号> PRODUCT=xiaotu tools/release/publish_macos.sh`。脚本会上传 dmg、用 `manifest_v2.py` 生成并签 `manifest.json`、生成 `appcast.xml`、本地验签、下载预热（无 CDN 层，默认不 purge；下载页由 `site.js` 读清单自动同步）；漏掉这一步，客户端会持续提示有新版却拿不到包。已发版本补/改发行说明用 `NOTES_ONLY=true tools/release/publish_macos.sh`（或 `publish_windows.sh`），只上传说明页并重签清单，不重出包。
- 已实现：自动检查与后台预下载两个开关（默认开，关于页可改）、首次下载流量提示、进度与取消、预下载失败按 60s/600s 退避最多 3 次、单包清理；壳内校验 `platforms.macos`、`min_os` 与 `rollout_percent`（v2 无 API/schema 区间；强制更新绕过灰度）；`mandatory` 阻塞提示（含重新下载大小与截止时间）；服务端 `min_supported_version` 握手阻断。
- 安装链路：macOS 发布构建由 Sparkle 统一下载、验签、原子替换并自动重启，不再打开 dmg 让用户拖拽；自研后台预下载在 Sparkle 构建中已停用。恢复模式与旧版本回退已实现并完成真机演练（连续 3 次启动失败后可在关于页一键回退，替换 `.app` 后重启已实测）；Windows 桌面端更新桥与前端「软件更新」卡片已接入，1.0.6 真机验收通过；分发仍以手动下载为主。灰度放量使用 `tools/package/rollout_oss.sh`（默认 1% → 10% → 50% → 100%，每档 24h，可按平台）；历史包用 `tools/package/cleanup_oss_versions.sh` 清理（默认保留最近 3 个，v1/v2 命名都识别）。
- 网络版服务端已接入厂商清单（`[update] manifest_url`，验签后缓存、失败回退），安装经确认后自动替换程序并重启，失败回滚；Windows 桌面端更新桥与前端「软件更新」卡片已接入，1.0.6 真机验收已过，分发仍以手动下载为主。

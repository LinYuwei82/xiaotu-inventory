# 发行与安装说明

当前版本 0.9.0。分发方式、未签名安装步骤、手工发包清单与将来购证清单统一放在本文件。

## 1. 当前分发方式（已定）

- **手工分发**：前几个客户由开发者直接发送 dmg / 安装包，不提供下载站。
- **不启用更新清单**：`latest.json` 与客户端自动更新检查暂停，更新链路代码保留但未启用。
- 原因：更新清单一上线就必须每次发版同步，否则客户端会持续提示有新版却拿不到；客户数与发版频率稳定后再评估。
- 分发时同时发出安装包、`SHA256` 校验值与本文第 2 节，并请客户「装完回一句能不能打开」。

## 2. 未签名安装说明（给客户）

两个平台都**没有购买代码签名证书**，因此首次打开会被系统拦一次。这是签名缺失，不是安装包损坏。

### macOS

1. 双击 dmg，把「小兔进销存」拖进「应用程序」。
2. 首次打开：在应用上**右键 →「打开」**，弹窗里再点「打开」；
   或在「系统设置 → 隐私与安全性」底部点「仍要打开」。
3. 每个用户、每台机器只需放行一次；后续正常双击。
4. 仍被拦截时，可在终端执行：
   ```bash
   xattr -d com.apple.quarantine "/Applications/小兔进销存.app"
   ```

### Windows

1. 运行 `xiaotu-inventory-0.9.0-win64-setup.exe`。
2. 若出现「Windows 已保护你的电脑」：点「更多信息」→「仍要运行」。
3. 每个用户首次运行只需放行一次；安装过程不需要管理员权限。
4. 安装路径为 `%LOCALAPPDATA%\Programs\小兔进销存`，数据在 `%LOCALAPPDATA%\com.simem.xiaotu`。

## 3. 手工发包清单

发版前逐条打勾：

- [ ] 工作区干净，`git status` 无未提交改动。
- [ ] `bash tools/ci/check.sh` 完整通过（含 codegen、第三方补丁、前端语法、平台泄漏与 ctest）。
- [ ] `VERSION` 已改为目标版本，`README` 标题与版本说明同步。
- [ ] 打 tag：`git tag v<版本>`，推送 tag 与 `main`。
- [ ] macOS：`tools/package/make_dmg.sh`，得到 `build/package/xiaotu-inventory-<版本>.dmg`。
- [ ] Windows：`windows-release` 构建后生成安装包，或从 CI artifact `xiaotu-win-installer` 取包。
- [ ] 核对 Windows 包内 `SIGNING.txt` 写的是「未签名」。
- [ ] 对每个产物计算并记录 SHA256：`shasum -a 256 <文件>`。
- [ ] 附上本文第 2 节，并明确「首次打开需手动放行一次」。
- [ ] 给客户一句话：「装完回我一句能不能正常打开」；收到回复后记录客户、系统版本与结果。

## 4. 将来购买证书时要做的事

### macOS

1. 申请 **Apple Developer Program 个人账号**（年费 99 美元），主体与发布署名一致，为个人 `si_mem`。
2. 在开发者后台创建 **Developer ID Application** 证书，导入本机钥匙串。
3. 打包时设置环境变量 `XIAOTU_SIGN_IDENTITY`（`tools/package/make_dmg.sh` 读取）；`packaging/mac` 相关脚本按该变量切换 ad-hoc 与正式签名。
4. 公证：用 `notarytool submit` 提交 dmg，成功后 `stapler staple` 装订；凭据建议存钥匙串 profile，不写进仓库。
5. 复核 `spctl -a -vv` 与 `codesign -dv` 输出；更新 `tools/package/README.md` 与本文第 2 节。

### Windows

1. 购买 **OV 代码签名证书**（文件或云签名均可）；EV 可选，能更快建立 SmartScreen 信誉。
2. 在 GitHub 镜像仓库配置两个 secret：`WINDOWS_CERT_PFX_BASE64`（PFX 的 Base64）与 `WINDOWS_CERT_PFX_PASSWORD`。
3. `.github/workflows/windows-build.yml` 的签名步骤已存在：检测到 secret 时调用 SDK 的 `signtool.exe`（SHA256 + RFC3161 时间戳），缺失则跳过并写 `SIGNING.txt`。
4. 用 `signtool verify /pa /v` 校验安装包与卸载器；确认 `SIGNING.txt` 变为「已签名」。
5. 更新 `packaging/win/README.md` 与本文第 2 节，删除「未签名」提示。

## 5. 更新链路现状

代码已就绪：更新清单解析、`0.9.0 < 0.10.0` 这类数字段比较、灰度字段、清单验签钩子均已实现并有测试。

但当前**未启用**：没有部署 `latest.json`，客户端不会主动检查更新。将来启用时只需配置 `[update]` 段与清单文件，不需要改代码；启用后每次发版必须同步清单，否则会出现「提示有新版但拿不到」。

# 发行与安装说明

当前版本 0.9.0。分发方式、首次打开的放行方式、发版清单与签名状态统一放在本文件。

## 1. 当前分发方式（已定）

- **下载页 + 应用内更新（macOS）**：安装包与清单发布在 `https://dl.xiaotu.online/`（阿里云 OSS 香港 + CDN），macOS 应用启动 30 秒后自动检查，之后每 24 小时检查一次，发现新版本后由用户确认安装。
- **清单已启用**：`https://dl.xiaotu.online/xiaotu/updates/stable/latest.json`，`appcast.xml` 在同一目录。每次发版用 `tools/package/publish_oss.sh` 同步；不发版不要手改清单，否则客户端会提示有新版却拿不到包。
- **Windows 仍为手动分发**：不接自动更新，由客户从下载页获取安装包。
- 分发时同时发出下载页链接与本文第 2 节。

## 2. 首次打开的放行方式（给客户）

macOS 包已用 Developer ID 签名并公证 + staple，正常双击即可打开；Windows 安装包未签名，首次打开会被系统拦一次。这是签名缺失，不是安装包损坏。

### macOS

1. 双击 dmg，把「小兔进销存」拖进「应用程序」。
2. 正常双击打开，不需要右键放行。
3. 如仍被拦截，先确认包来自 `https://dl.xiaotu.online/`；再在「系统设置 → 隐私与安全性」底部点「仍要打开」，或执行：
   ```bash
   xattr -d com.apple.quarantine "/Applications/小兔进销存.app"
   ```

### Windows

1. 运行 `xiaotu-inventory-0.9.0-win64-setup.exe`。
2. 若出现「Windows 已保护你的电脑」：点「更多信息」→「仍要运行」。
3. 每个用户首次运行只需放行一次；安装过程不需要管理员权限。
4. 安装路径为 `%LOCALAPPDATA%\Programs\小兔进销存`，数据在 `%LOCALAPPDATA%\com.simem.xiaotu`。

## 3. 手工发包清单

- [ ] `VERSION` 已改为目标版本，`README` 标题与版本说明同步。
- [ ] 打 tag：`git tag v<版本>`，推送 tag 与 `main`。
- [ ] macOS：带签名与公证参数跑 `tools/package/make_dmg.sh`，得到 `build/package/xiaotu-inventory-<版本>.dmg`。

- [ ] Windows：`windows-release` 构建后生成安装包，或从 CI artifact `xiaotu-win-installer` 取包。
- [ ] 核对 Windows 包内 `SIGNING.txt` 与安装包签名状态一致（未签名，或已签名且 Authenticode `Valid`）。
- [ ] 从下载页实际下载一次，挂载后确认 `codesign --verify --deep --strict` 与 `spctl -a -vv` 通过。
- [ ] 用旧版本客户端实跑一次自动更新，确认弹窗、下载、替换与重启。
- [ ] 附上本文第 2 节（Windows 未签名时需手动放行）。
- [ ] 给客户一句话：「装完回我一句能不能正常打开」；收到回复后记录客户、系统版本与结果。

## 5. 更新链路现状

- macOS 单机版已启用并端到端实测：启动 30 秒首查、之后 24h±2h；清单 Ed25519 验签；发现更高 build 后中文 Sparkle 弹窗确认，下载并原子替换 `/Applications/小兔进销存.app`，重启后构建号更新，`codesign --verify` 与 `spctl -a -vv` 通过。清单检查失败按 1 分钟 / 10 分钟 / 1 小时退避，成功一次即恢复 24h 节奏。
- 发版必须同步清单：`PRODUCT=xiaotu tools/package/publish_oss.sh`。脚本会上传 dmg、生成并签 `latest.json` / `appcast.xml`、本地验签、purge CDN、回写下载页数字并预热 CDN；漏掉这一步，客户端会持续提示有新版却拿不到包。
- 已实现：自动检查与后台预下载两个开关（默认开，关于页可改）、首次下载流量提示、进度与取消、预下载失败按 60s/600s 退避最多 3 次、单包清理；壳内校验 `min_os`、API 区间、schema 与 `rollout_percent`（强制更新绕过灰度）；`mandatory` 阻塞提示（含重新下载大小与截止时间）；服务端 `min_supported_version` 握手阻断。
- 尚未实现/限制：Sparkle 复用预下载包（安装时仍会重新下载）；自动放量脚本；恢复模式一键回退的“替换 `.app` 后重启”真机演练。恢复模式与旧版本回退主体已实现（连续 3 次启动失败后可在关于页一键回退）；Windows 桌面端仍为手动下载安装。
- 网络版服务端已接入厂商清单（`[update] manifest_url`，验签后缓存、失败回退），安装经确认后自动替换程序并重启，失败回滚；Windows 桌面端仍为手动下载安装。

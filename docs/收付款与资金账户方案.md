# 收付款单与资金账户：表结构方案（待确认）

> 状态：**方案稿，未改任何代码**。确认后再按第 9 节分步实施。
> 版本位置：数量精度占用 v11，本方案为 **v12**，纯增量，不改 v1–v10，不动历史金额。
> 基准提交：`f81a383`（schema v10）。

## 1. 结论摘要

- 新增 `fund_account`（资金账户档案），`settlement` 原地升格为收/付款单，**不新建第二套单据表**。
- `direction` 保持唯一语义：`1` = 收款（对应应收），`-1` = 付款（对应应付）。不额外加 `voucher_type` 列，界面文案按 `direction` 显示「收款单 / 付款单」。
- 不另建资金流水表：账户余额 = 期初 + `settlement` 汇总；撤销行是负数记录，天然回冲。不做余额缓存列。
- 分摊表 `settlement_allocation` 结构不动；分摊变为**可空**：没有分摊的收款单就是预收/预付（未核销金额 = 单据金额 − 已分摊）。
- 老记录 `account_id = 0`，列表标注「未指定账户」，不计入任何账户余额；不强行归到「现金」。迁移只新建一个可用的「现金」账户供新单据使用，不回填老数据。
- 新增权限 `fund.read` / `fund.write`：账户档案属于资金基础设置，操作员可读、仅管理员可写；收付款单继续用现有 `finance.read/write`。

## 2. `fund_account` 表

```sql
CREATE TABLE fund_account (
  id            INTEGER PRIMARY KEY,
  code          TEXT    NOT NULL,
  name          TEXT    NOT NULL,
  kind          TEXT    NOT NULL,
  account_no    TEXT    NOT NULL DEFAULT '',
  bank_name     TEXT    NOT NULL DEFAULT '',
  opening_cents INTEGER NOT NULL DEFAULT 0,
  sort_order    INTEGER NOT NULL DEFAULT 0,
  status        INTEGER NOT NULL DEFAULT 1,
  is_deleted    INTEGER NOT NULL DEFAULT 0,
  created_at    TEXT    NOT NULL,
  created_by    TEXT    NOT NULL DEFAULT 'system',
  updated_at    TEXT    NOT NULL,
  updated_by    TEXT    NOT NULL DEFAULT 'system',
  CHECK (kind IN ('CASH', 'BANK', 'WECHAT', 'ALIPAY', 'OTHER')),
  CHECK (description_placeholder = '')
);
```

（上一行占位需删除；正式列定义见下。）

字段说明：

| 字段 | 说明 |
| --- | --- |
| `code` | 账户编码，唯一；新账户手填或按 `CASH` / `BANK001` 规则建议 |
| `name` | 账户名称，唯一（避免出现两个「现金」） |
| `kind` | 现金 / 银行 / 微信 / 支付宝 / 其他 |
| `account_no` | 账号，非银行账户可为空 |
| `bank_name` | 开户行，仅银行账户使用，可为空 |
| `opening_cents` | 期初余额（分），允许为负（信用卡/透支），默认 0 |
| `sort_order` | 列表与下拉排序，默认 0 |
| `status` | 启用/停用；停用后不出现在新单据下拉，但历史流水照常展示 |
| `is_deleted` | 软删除；被 `settlement` 引用过的账户只允许停用，不允许删除 |

约束与索引：

```sql
CREATE UNIQUE INDEX uk_fund_account_code ON fund_account(code);
CREATE UNIQUE INDEX uk_fund_account_name ON fund_account(name);
CREATE INDEX idx_fund_account_sort ON fund_account(sort_order, id);
```

**期初余额不另起「期初资金」单据**：期初是账户的状态而不是一笔业务，用单据承载会多一条只跑一次的路径，还要处理重复期初、撤销期初。直接在档案里维护，修改期初写审计日志（`entity=fund_account, action=update`），资金流水报表在区间起点前插入「期初」行展示它。

## 3. `settlement` 升格

新增列：

```sql
ALTER TABLE settlement ADD COLUMN account_id INTEGER NOT NULL DEFAULT 0;
ALTER TABLE settlement ADD COLUMN method     TEXT    NOT NULL DEFAULT '';
ALTER TABLE settlement ADD COLUMN operator   TEXT    NOT NULL DEFAULT '';
CREATE INDEX idx_settlement_account_date ON settlement(account_id, settled_on, id);
```

| 列 | 新单据要求 | 老数据回填 | 说明 |
| --- | --- | --- | --- |
| `account_id` | **必填**，必须是启用状态的账户 | `0` | 0 显示「未指定账户」，不参与账户余额 |
| `method` | **必填**：`CASH`/`BANK`/`WECHAT`/`ALIPAY`/`OTHER` | `''` | 与账户类型可以不同（例如银行账户走微信收款）；空串显示「未记录」 |
| `operator` | 选填，默认取当前登录用户 | `''` | 经办人，可能不是系统操作人；`created_by` 仍保留「谁录入」 |

不加 `status` 列：撤销通过 `reverses_id` 负数行表达，现有机制不变。

**单据类型与方向**：`direction = 1` 为收款单，`-1` 为付款单，与 `ar_ap_entry.direction` 完全一致。不引入第二套类型字段，避免两处口径冲突。

**单号前缀**：新单据按方向区分——收款 `SK`、付款 `FK`，格式 `SK20261112-0001`；老单号 `HX...` 原样保留，不重编。唯一索引 `uk_settlement_no` 覆盖两种前缀，按前缀分段取号，互不影响。

**往来单位**：`partner_key` / `partner_name` 改为创建时的入参（老逻辑是从分摊反推）。新单据必须从客户或供应商档案选择，写入 `C:<id>` / `S:<id>` 与名称快照；`T:` 文本键只允许在带分摊的老式录入里出现。这样预收/预付也能落到具体往来单位。

## 4. 资金流水与余额

不新建流水表，直接由 `settlement` 派生：

```text
账户余额 = opening_cents
         + Σ(direction = 1  ? amount_cents : -amount_cents)   // 收款加、付款减
```

- 撤销单与原单同账户、同方向、金额为负，汇总时自动回冲，余额不会残留。
- 余额不缓存：`idx_settlement_account_date` 覆盖按账户 + 日期查询，量级是「每月几十到几百条」，实时求和足够；等单账户流水到十万级再考虑缓存列（届时用同事务维护）。
- 账户停用不影响历史流水与余额展示；删除账户前检查 `settlement.account_id` 是否引用，引用则只允许停用。
- 老数据 `account_id = 0`：资金流水默认按账户筛选时不出现；报表提供「未指定账户」分组，避免历史金额凭空消失。

## 5. 与核销的边界

- 一张收付款单只对一个往来单位（沿用现有校验）。
- `settlement_allocation` 结构不变；分摊从「必须等于单据金额」放宽为「合计 ≤ 单据金额」：
  - 等额分摊 = 正常核销；
  - 小于单据金额 = 部分核销，剩余为预收/预付；
  - 分摊为空 = 纯预收/预付。
- 不加「预收」状态列，未核销金额由 `amount_cents − Σallocation.amount_cents` 派生，避免状态与金额两套事实。
- 反向校验保留：分摊只能命中同一往来单位、同一方向、未作废且未超额的单据。
- 后续把预收转核销时，新增一张收款单做分摊即可（或做「预收转核销」专用操作，本期不做）。

## 6. 报表

新增「资金流水（现金日记账）」：

| 列 | 内容 |
| --- | --- |
| 日期 | `settled_on` |
| 单号 | `settle_no` |
| 类型 | 收款 / 付款 |
| 往来单位 | `partner_name` |
| 结算方式 | `method` 的中文 |
| 经办人 | `operator`，空则显示录入人 |
| 摘要 | `note` |
| 收入 / 支出 | 收款为正列收入，付款为正列支出（金额都显示正数） |
| 余额 | 期初 + 逐行累计，整数分计算 |

- 排序：`account_id, settled_on, id`；同一账户内按日期、再按录入顺序。
- 期初行：区间起点之前的所有流水汇总 + `opening_cents`，作为第一行「期初余额」；若区间起点就是账户开立日，期初行等于档案期初。
- 筛选：账户（必选或「全部账户」）、日期范围。
- 导出：CSV / XLSX 沿用现有报表通道；打印加一个 `REPORT` 目标 `fund_ledger`，列定义与现有报表一致。
- 另加「账户余额一览」：账户、类型、期初、累计收入、累计支出、当前余额，可按日期截止。

老 `settlement` 行 `account_id` 保持 0、`method`/`operator` 为空，不做 UPDATE；金额、分摊、单号一律不动。

迁移版本、checksum、`user_version` 与迁移前自动备份沿用现有机制：v11 → v12 会先写 `backups/app-<时间>-pre-v11.db`。回滚必须连库一起回退，旧程序不认识新表与新列。

## 8. 权限与页面影响

**权限建议：新增 `fund.read` / `fund.write`。**

- 理由：账户档案决定资金口径（期初、账户归属），写权限不应跟着 `finance.write` 下放给操作员；但开收付款单必须能读账户下拉，所以给操作员与只读 `fund.read`。
- 收付款单本身仍用 `finance.read` / `finance.write`，不新增第三组权限。
- 若希望「操作员也能建账户」，可以只在 v12 种子行里给 operator 加 `fund.write`，其余不变。

**页面改造：**

| 页面 | 改动 |
| --- | --- |
| 「应收应付」→「收付款」 | 顶部按收/付切换；列表增加账户、结算方式、经办人、未核销金额；新建表单改为选往来单位 + 账户 + 方式 + 金额 + 可分摊明细（可为空）；撤销沿用负数行 |
| 资金账户档案（新页） | 列表（编码、名称、类型、账号、期初、排序、启用）+ 新建/编辑/停用；`fund.write` 才显示写操作 |
| 资金流水（新页，或并入报表） | 账户 + 日期范围筛选，含期初行与余额列，CSV/XLSX/打印 |
| 对账单 / 打印模板 | 暂不改；`settlement` 打印目标如后续需要再单独加 |

现有 `financePage` 的「选中一张应收单，全额核销」交互保留为快捷方式，底层改调新的收付款接口。
